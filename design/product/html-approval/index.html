Approving a remote host

A previewed HTML page asks for a font, a script, an image from somewhere on the internet. Erfana blocks it and asks you. This is how that conversation should go.

What this replaces. Each blocked host used to raise its own pop-up, capped at three. A page reaching four hosts produces three stacked walls of identical text over your file tree — and the fourth host cannot be approved at all, because the app ran out of pop-ups. That cap was the only thing bounding the list, so it was load-bearing by accident.

Four rules this design follows

1 · The question lives on the thing it is about. A permission decision outlives the message that raised it, so it belongs on the preview's own chrome — not floating over an unrelated part of the app that happens to be free.

2 · One decision at a time, and never by accident. Allow only opens the question. Confirm answers it, and is deliberately not focused, so pressing Return twice cannot grant anything.

3 · Say what is actually being granted. Erfana cannot limit a host to the one thing it was blocked for. Approving lets that host serve code and receive data, in every preview in the project, for anyone who clones it. The confirm step says so in those words.

4 · Never draw a button a page could be sitting on top of. The previewed page is a native layer above all of Erfana's own interface. Buttons appear only once the page has proved it moved out of the way — see step 8.

The keyboard route

A preview is a trap without this: focus goes into the page and there is no documented way out.

Escape leaves the page. When the find bar is closed, a forwarded Escape returns focus from the previewed page to the band's chip. No new shortcut is invented, and the chip's name says so out loud — which is what WCAG 2.1.2 asks for: not just an exit, but a stated one.

The chip is an ordinary Tab stop in the panel's chrome. From there: Enter opens the list, ↑ ↓ move between hosts, Enter on a row starts the approval, Escape steps back one level at a time — confirm, then list, then page. Opening the list with the keyboard moves focus to the first Allow; opening it with the mouse does not, because the pointer already knows where it is.

What it deliberately does not do

Not thisWhy
Approve everything at onceA single click granting four hosts is not a decision, it is a dismissal. The list stays a list.
Remember "always allow this host everywhere"The grant is per project on purpose. A global allowlist would follow you into repositories you did not write.
Animate openAn eased height races the native page, which moves in one step, and exposes page pixels underneath the buttons mid-animation.
RevokeNot built yet — issue #86. This design delivers the seeing half, which is why the allowed list is read-only here.
Colour-code the riskEvery host in the blocked list carries the same risk once approved. Tinting some of them green would be a lie.
