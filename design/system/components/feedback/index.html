Decision one — which amber is "warning"

Erfana declares tokens for the meaning "warning" and for "error". The toast — the surface users see most — is the odd one out, using an icon tint rather than the warning colour. The semantic tokens win. Everything else is retired for this purpose, and the retired ones now say so in design-tokens.css.

Those two numbers count declared tokens, and the basis matters. This card previously said "four warning, three error" with no basis given — it was both wrong and unfalsifiable, because nobody could tell whether it meant tokens, literal values, or foreground hues. A count with no stated denominator is not evidence.

Decision two — one banner

Four severities, one shape: an icon, a title, a sentence, and — when there is something the reader can do — one action. Erfana has this pattern duplicated under two class prefixes that have already diverged, plus three unrelated full-panel variants.

An error names the way out. "Could not save" is half a message. What went wrong, and what the reader can do about it — no apology, no stack trace, no blame.

The same message deserves the same quality everywhere. Today "this file was deleted on disk" is a proper alert with an icon and a Reload button in the image viewer, and a bare unlabelled <div> with no way to recover in the markdown editor.

Decision three — telling a screen reader

Erfana has four incompatible strategies for this, and three of them are unreliable. role="alert" alone appears in files — the most-used of the four, and the one whose own comments call it unreliable. Only one is correct, and it is already in the toast module.
ApproachVerdict
A hidden region that is always mounted and empty until there is news This one. The browser watches the region for changes. It has to exist before the text arrives.
role="alert" on a box that appears at the same moment as its text Unreliable. There was nothing to watch until the moment it changed. Erfana's own code comments say so, and five surfaces do it anyway.
Move focus and hope aria-describedby gets read Works only when focus genuinely should move. Not an announcement mechanism.
A region that unmounts when idle Same failure as the second. It does not exist until it matters.
Politeness. aria-live="polite" for everything — it waits for a pause. assertive interrupts whatever the person is reading, so it is for errors only.

Reserve the height. A message appearing in an empty region shoves the page down. The crash screen reserves two lines for exactly this reason, and nothing else does.

Toast, or banner?

Use a toast whenUse a banner when
It is finished and needs no reply — "Exported to PDF". It may vanish because nothing is lost if it is missed. It is about the thing on screen, or the reader has to decide something. It stays until the situation changes.
A permission is never a toast. Approving a remote host is a decision with consequences that outlive the message, so it belongs on the surface it affects — see the Permission band card. This card exists partly because that rule was learned the hard way.
