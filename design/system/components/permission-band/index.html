Permission band

A preview page that asks for a remote host gets one row here, not a toast. Click the chip to open it. Click Allow, read the confirm step, then Confirm or Cancel. Press Escape to close.

The band's own text is measured, not assumed. Its labels use --color-text-tertiary, which is :1 on the band — clear of the 4.5:1 floor. The obvious-looking --color-text-secondary is :1 on the same surface and fails, which is why it is not used here.
Why this replaces the toast. Approval used to be a pop-up per host, capped at three. A page reaching four hosts produced three stacked walls of identical text over the file tree — and the fourth host could not be approved at all. The band lists every host, in the preview's own chrome, and each decision is read once on the row it belongs to.

Drag below ~320px. A 64px sliver of page is not a preview, so the band hides the page instead of insetting it.

The page has 300 ms to acknowledge that it moved. Silence means "assume it is still covering you" — so the page is hidden and the band says so.

Writing .erfana/settings.json can fail — a read-only checkout, a full disk. The row then says Not saved, and the chip keeps a red caret so the failure survives collapsing the list. Until this button existed the state was unreachable: failed was only ever assigned null, so the card described a state it could not render.

What the confirm step has to say, and why

The kind column ("script", "image") says what the host was blocked for — not what you are granting. Erfana cannot narrow a grant to one kind: an approved host is added to every CSP directive the preview builds, so it can serve code and receive data. The confirm step says that in plain words rather than letting the column imply otherwise.

It also says the grant is written into the project, travels to anyone who clones the repository, and cannot be undone from inside Erfana. That is the honest sentence — and it is read once, on the row you chose, instead of four times over your file tree.

Which is why an allowed row shows no kind at all. The same word that is a fact on a blocked row — "this was refused, for a font" — becomes a claim about scope on an allowed one, and the scope is not real. The allowlist stores hosts and nothing else, so for a host approved last month the kind is unknowable anyway; filling the column for this session's approvals only would invite the reader to infer a difference in grant that does not exist.

Exceptions

Where the shipping component departs from this card, with the reason. An undocumented deviation is a bug; a documented one is a decision.

Focus after Cancel, and after a failed approval Returns to the chip. Returns to the Allow button that opened the question. The card has no choice: its render() does scroll.innerHTML = '', so the invoking button no longer exists — the same trap recorded in focusConfirm(). React keeps the row, so the standard dismiss-to-invoker behaviour is available and is what the product card's "steps back one level at a time" describes. After a successful approval the row genuinely is gone, and both agree on the chip.
Confirm Answers immediately. Is an async IPC round trip, followed by a CSP rebuild and a reload. Confirm carries aria-disabled while the write is in flight, and Escape is ignored in that state — there is no safe way to cancel a write already sent.
