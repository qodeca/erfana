## 3. Work plan

### Step A – setup

```
git fetch origin && git checkout develop && git pull
git rev-parse --short HEAD   # expect 94e6396a or newer – say which
npm ci                       # never npm install (drops encoding@0.1.13 from the lock)
```

Node 24; Python 3.12 or 3.14.x (not 3.13 – node-pty).

### Step B – full local gate on macOS

```
npm run lint:check && npm run lint:css && npm run design -- --check && npm run check:headers && npm run check:links
npm run typecheck
npm run test:cov              # every unit/integration test once + all coverage floors
npx electron-vite build
npm run test:e2e:no-build     # after the build above; E2E does not run in CI
```

Use `lint:check`, not `lint` (`lint` runs `--fix`). Record pass/fail and exact output for any failure. For an e2e failure, rerun it focused (`--repeat-each=5 --workers=1`) before calling it a flake, and never call it a flake without that.

### Step C – macOS-specific manual checks (the gate does not cover these)

Run the app (`npm run dev` or the built app) and check:

1. **⌘W** on a tab you just typed in → "Unsaved Changes" warning; Cancel keeps the tab; a clean tab closes with no prompt; only the active tab closes (#220).
2. **Tree refresh**: create/rename/delete a file from the terminal while Erfana is open → tree updates by itself (#211 watcher-after-first-load, #213).
3. **Git status** still updates after a commit/checkout in the terminal – chokidar no longer watches `.git` on macOS; `GitWatcherService` must cover it (#211).
4. A project stored **inside a folder named `build`, `out` or `dist`** refreshes on its own (#211).
5. `files.exclude` in `.erfana/settings.json` hides and stops watching a folder (#211; see `docs/user-guide/reference/settings.md#excluded-folders`).
6. Find bar option shortcuts use ⌘-based bindings (#148).
7. `npm run build:mac` succeeds (dependency bumps #193/#194).

Fix on a branch off `develop` (`fix/…`), PR, merge through the queue (see section 5).

### Step D – release v0.21.0

Only when B and C are clean. Use the **`releasing-erfana`** skill; it owns the procedure (main-branch discipline, notes, signed tag, pipeline, artifact verification, publish gate). Items the skill or CLAUDE.md require that are easy to miss:

- **Windows status snapshot**: `docs/windows/implementation-plan.md` → "Status snapshot" is anchored on v0.20.0 (2026-09-15). This release touches Windows scope (#208, #211, #221), so re-anchor it on v0.21.0 before tagging (CLAUDE.md refresh policy; the release-quality-runner checks it).
- **CLAUDE.md** "Current version" line → v0.21.0.
- **`main` lags `develop`**. `main` rejects a SHA whose required checks are not green (`GH006`) – push to `develop` first, wait for the run, then fast-forward `main` (CLAUDE.md § Branching model).
- `npm audit --omit=dev --json` must be diffed against `docs/security.md` → "Accepted exceptions for v0.21.0" (#162, owner decision 2026-09-26: `electron`, `extract-zip`, `@llamaindex/liteparse`, `sharp`). Any new production advisory blocks the release (policy: zero high/critical outside that table).

## 4. Repo facts learned in this session

- `develop` has a **merge queue**. `gh pr merge` fails; enqueue via GraphQL `enqueuePullRequest` with the PR node id. Delete a PR's branch only after `gh pr view N --json state` says `MERGED` – deleting earlier auto-closes the PR.
- The `bash-safety` hook blocks `rm -rf` on some paths; ask the user to run such a command with `!` if needed.
- Remote branches were cleaned today: only `main`, `develop`, `graph`, 12 Dependabot branches and `xez/347fc1ce` (#167) / `xez/43131e43` (#168) remain.
