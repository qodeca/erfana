## 3. Finding on the first final gate, fixed in #379

The first final gate ran on `76076ffb`. Every step passed except `npm run test:e2e`: "2 failed, 2 skipped, 363 passed (20.6m)".

- **Failed**: `e2e/project-switch-unsaved.e2e.ts` › "rapid double switch: the second project wins, with one toast and no tree from the first" (line 281), and in the full run only, › "discard does not write late…" (line 228). Run alone with `--repeat-each=3`, the first case failed 3 of 3.
- **What the user sees**: a false "Failed to Load Project" error toast with "Cannot read files outside the project directory", after two quick project opens.
- **Cause**: main commits the new project, then waits for the settings save, then broadcasts the change. The renderer's first tree read for the older project can land in that gap. Main then refused it as outside the project, and the renderer's guard for a stale load did not cover that answer. Windows makes the gap wider, because the settings save is slower there.
- **Bisect** (the first case, 3 runs each): `19bf1843` 3 passed · `45bfdbd7` 3 passed · `d8e2ae6c` 3 passed · `9dae4c7f` (#339) 3 failed · `76076ffb` 3 failed. The gap is older; #339 keeps error toasts until they are dismissed, so the test now sees the toast (inferred).
- **Fix**: [#379](https://github.com/qodeca/erfana/pull/379) – the first tree read names the project generation, and main answers a stale read with `PROJECT_CHANGED`, which the renderer ignores. On the #379 head `63ecac79`: the file `--repeat-each=3` "15 passed (1.3m)", full `test:e2e` "365 passed (18.6m), 2 skipped", and the rest of the gate exit 0.

## 5. Not run, and why

- **Terminal Recheck (#374)**: the "Terminal not available" state could not be forced on this host; with node-pty's native files hidden, the terminal still started. All files were restored.
- **A live terminal that reports a write or resize error**: no way found to force it from outside.
- **Restoring a deleted folder does not clear the "(deleted)" mark on its tabs**: an older limit, the same on `develop` before #346 and #375.
- **Signed build**: no `AZURE_TENANT_ID` on this host. Only the unsigned `--dir` build was used.
- The other Wave 2 owner decisions still hold – see the [Wave 2 report § 6](2026-10-23-windows-v0.22.0-wave2-report.md#6-owner-decisions-closed-not-run).
