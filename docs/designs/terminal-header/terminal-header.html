Terminal header at the default width

proposed not yet reviewed

At the default terminal width (300 px) the header keeps the four capture buttons and moves Scroll to bottom, Restart terminal and Lock scroll to bottom into the … menu (#462). This screen draws that, and two ways to keep the terminal's own buttons in the row. Both apply the Toolbar overflow card (decided) unchanged – they change only the toolbar's order, its button gap or its buttons. The owner picks one; the card records it.

Today, on macOS and Windows

Both platforms show all eight buttons (screen capture is supported on both; Linux has no screen capture, so its five buttons all fit and it has no … at this width).

Option A – one Capture menu button

The three screenshot buttons and the camera become one icon-only Capture button (the camera glyph) that opens a menu – a menu button, like …: aria-haspopup="menu", aria-expanded, named “Capture”. The row holds five buttons and no …, with room to spare. If the panel is narrowed until Capture itself moves, its four items join the … menu as one separated group – never a submenu (the Menu card has none and asks not to add one). On Linux, where only the camera exists, the Capture button is the plain Capture photo button.

Option B – terminal actions first, a tighter gap

Reorder so the actions on the terminal's output lead and leave last: Scroll to bottom, Lock scroll to bottom, then Capture screen, window, area and photo, then Restart terminal, with Maximize still raised. The button gap goes from 8px to 6px – the Project panel's row already uses 4px. Restart is placed to move first on purpose: it is a recovery action used rarely, and it ends whatever the agent is running, so it is better one deliberate click away than beside the buttons pressed all day.

The pixel budget at the default width

The header measures its own box (useToolbarOverflow) and hands the widths to computeOverflow: the buttons get what is left after the padding, the icon and the title's reserve – the title's text width never counts, so a shorter title gains nothing. Every button and … is 24px wide.

Exceptions

None recorded. Neither option needs one: rule 4 lets a toolbar choose its order and raise a button, and the gap is the panel's own (--erf-toolbar-overflow-gap).
