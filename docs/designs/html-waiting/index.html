Waiting for a page

A user opened a page and got a black rectangle for twenty seconds with no words on it. They filed it as a bug. It was not one – the page was loading. This screen decides what that rectangle says, when it starts saying it, and who it names.

What ships and what is proposed. The band in every frame is the one that ships (PreviewChromeBand, PreviewNavControls, PreviewToolbarTools), drawn with the decided Permission band card's markup. The waiting message (Surface A) and the residual line (Surface B) are not built. Surface A is this screen's proposal: the States pattern's inline, words-only wait. Surface B is the Permission band card's rule, decided by the owner on 2026-10-28: the bar's load status slot, drawn with the Toolbar card's .erf-toolbar__status. This screen still decides when it shows.
The rule. Erfana keeps the rectangle until the page has something to show. A native view that has painted nothing is not put on screen; until then the rectangle belongs to Erfana's own placeholder, which is where the wait is explained. This costs nothing: before first paint the native view paints the same backdrop colour the placeholder already carries, so no pixel the user has seen changes. What is gained is a surface where text, a focus ring, a button and a live region all work – none of which is possible over a native view.

The irony this exists to cover

A blocked origin is refused instantly. An approved one is not: Erfana steps out of the way and the browser really tries to reach it, so a host that never answers now costs a full DNS or TCP timeout. A render-blocking tag in <head> holds the page blank for that whole wait. Granting the permission is what makes the preview look dead. And there is no revoke yet (#86), so one bad approval slows that page for good. This screen cannot fix that. It can stop the user thinking Erfana broke.

The timeline, as a filmstrip

The proposed thresholds – 600 ms and 10 s – applied to three pages. Each cell is the state the rectangle is in for that stretch of time. The state machine is one pure function of elapsed time: none before 600 ms, quiet until 10 s, then explained (naming the host when one is still open), and settled the moment the page paints. These are the States pattern's quiet, waiting and escalated steps.

Endings, and the two states that must show nothing

The thresholds, and why they are still proposed

AtWhat changesWhy this number
600 msQuiet line appears Under Nielsen's 1 s flow limit, so the message is up before the user forms the question – and roughly twice an ordinary local open, so a fast page never flashes it. The States pattern proposes a 400 ms show delay; see Deliberate differences.
10 sEscalates: names the host, offers Stop Nielsen's attention limit, and the States pattern's proposed escalation point. Erfana cannot offer an ETA, so the explanation has to be on screen when patience runs out.
The request filter's own timeoutNothing new here The request filter (DEFAULT_REQUEST_TIMEOUT_MS in PreviewRequestFilter.ts) already records network-timeout and the tab badge already counts it. Do not draw it twice.
Both numbers are chosen, not measured, which is why this screen is proposed. The rule – hold the rectangle, name who you are waiting for, never predict – is a contract. The milliseconds are a value still being chosen.

The words

Every clause has to be verifiable at the instant it renders. Erfana does not know whether the page will ever load, so it must never imply it will. Wording follows the Writing card.

StateCopyWhy it is true
QuietLoading this page
Nothing has been drawn yet.		Two facts, both observed. No promise.

This project allows that host, so Erfana is letting the page reach it and is waiting for a reply. Erfana cannot tell whether it will ever answer.		 A remote request only ever gets in flight through the allow branch, so “this project allows that host” is true by construction – redirect hops included, since each re-enters the filter on its own. Not “you approved it”: a checked-in .erfana/settings.json may be a teammate's doing.

Local file reads go through the same in-flight set, so counting them blindly would let Erfana blame the network for reading a file off disk. This variant is why the signal must say local or remote, not just “busy”.

The one line that dates fast: “Allowed hosts are listed in .erfana/settings.json. Removing one is a manual edit for now.” True today, and it is the only exit a user has. It comes out the day #86 ships – a deliberate stopgap, not a permanent instruction.

Where it lives, and why the page cannot reach it

The previewed page is a native view. It paints above all sibling DOM over its own rectangle, so you cannot put a spinner on top of it. That single fact rules out most designs and produces these two surfaces.

SurfaceWhereWhy the page cannot touch it
A – the messageInside the placeholder, the full rectangle It exists only before first paint, when the view is not on screen at all. A page that is not on screen cannot cover anything – the same reasoning the chrome gate already uses when it treats a hidden page as proving nothing.
B – the residual lineThe band bar's load status slot (Permission band card, decided) The band is a flow sibling above the page's rectangle (HtmlPreviewPanel.tsx:388-400), so the page has nowhere to paint that could reach it. The bar may grow, but each growth moves the native page – a bounds push and a fresh 300 ms proof – which a slow load does not justify. So the line is horizontal only.
Contrast is only knowable on Surface A because of when it exists. Pre-paint the backdrop is provably the brand black, so the text is measured against it. Both hints – the body and the aside about .erfana/settings.json – use the States hint colour, --color-text-tertiary, at 8.52:1. The aside used to be its own quieter style: --color-text-secondary at 5.00:1, and before that --color-text-muted at 3.62:1, a failure. It is now merged into the hint style, so there is one colour to keep honest.

Surface B sits on the band's --color-bg-primary: the status line (--color-text-tertiary) is 8.52:1, and the stopped line (--color-warning) is 8.00:1 · pass, with the warning icon beside it so the tone is not carried by colour alone (Permission band, load status slot). If either surface were ever allowed to render over the page's own paper – which the page chooses – the contrast would be uncontrollable. That timing is a precondition of the design, not a detail of it.

Precedence: only one thing may own the rectangle

There are four ways a preview can show no page, and they must not blur together.

SituationWaiting message?Why
Loading, nothing paintedShownThis is the case the screen is for.
Band's list is open, page pausedSuppressed Not a wait. A finished, deliberate Erfana action with a named cause and a known exit – collapse the list. Calling it “waiting” would suggest Erfana is stuck when it is not, and would bury the one instruction that ends it. It is also a security notice; diluting it into an ambient progress line is a loss.
Inactive tab showing its still frameSuppressed The frame already answers “what is here”. A panel nobody is looking at has no wait to report, and its live region must stay silent.
Splitter or window-edge drag, page frozenSuppressed Not a wait: the page is being resized, and returns the moment the drag ends. The still picture holds the rectangle at its captured size, top-left – or the page's own paper when the picture is out of date – and stays until the page is confirmed back on screen. No text, no spinner, no “Resizing” label, nothing announced (issue #124, UX §4).

RuleDecision
Politenesspolite at every stage, never assertive. A slow load is not an error.
How often it speaksAt most twice per load – once at the 10 s escalation, once when it ends – the States pattern's announcement budget. Nothing at 600 ms: that would fire on ordinary opens.
Target sizeStop is the States action, at least 24px tall; Reload is a band tool (.erf-band__tool), taller than that. Both are reversible.
Wrapping and translationSurface A wraps at the States hint measure, absorbing 40 % expansion. Surface B must not wrap – wrapping grows the band, which pushes the page – so it ellipsis-clips rather than reflowing.
Host namesThrough the existing .erf-host primitive (host.css). Do not re-implement the bidi handling.
Reduced motionNo animation at all – no spinner, no pulse, no progress bar (Motion). Case 09 above draws it beside case 02, so “there is nothing here to disable” can be checked by comparing them.
Why no spinner, put plainly. A spinner says “working”. It cannot say how long or on what, and those are the two questions the black rectangle provoked. Words say all three – which is the States pattern's rule for a wait on something outside Erfana.
A role this design has to change. The placeholder's role is img while the native view is hidden, button while the page can be entered, and group otherwise (HtmlPreviewPanel.tsx:454-463). Pre-paint the view is hidden, so today the placeholder would be an img exactly when Surface A is up – which makes its whole subtree presentational and puts Stop out of reach of a screen reader. While Surface A shows, the placeholder must be a group (it keeps aria-busy and its label). Found by reading, not by testing; it needs a test.

What this screen does not know

Open questionWhy it is not settled here
Does holding the view hidden throttle the page? Whether hiding a native view marks the document hidden and throttles it in this Electron version was not measured. Network fetches are not visibility-throttled and the app already hides previews on every tab switch, so the exposure looks small – but it must be measured before this screen is promoted.
What counts as “can draw”? There is no first-paint event available, so the release signal has to be dom-ready, which is a lower bound on painting, not painting. A bare render-blocking stylesheet can still hold the page blank afterwards. Surface B exists because of that gap.
