Waiting for a page

A user opened a page and got a black rectangle for twenty seconds with no words on it. They filed it as a bug. It was not one – the page was loading. This card decides what that rectangle says, when it starts saying it, and who it names.

The rule. Erfana keeps the rectangle until the page has something to show. A native view that has painted nothing is not put on screen; until then the rectangle belongs to Erfana's own placeholder, which is where the wait is explained. This costs nothing: before first paint the native view paints the same backdrop colour the placeholder already carries, so no pixel the user has seen changes. What is gained is a surface where text, a focus ring, a button and a live region all work – none of which is possible over a native view.

The irony this exists to cover

A blocked origin is refused instantly. An approved one is not: Erfana steps out of the way and the browser really tries to reach it, so a host that never answers now costs a full DNS or TCP timeout. A render-blocking tag in <head> holds the page blank for that whole wait. Granting the permission is what makes the preview look dead. And there is no revoke yet (#86), so one bad approval slows that page for good. This card cannot fix that. It can stop the user thinking Erfana broke.

The timeline, as a filmstrip

The real thresholds – 600 ms and 10 s – applied to three pages. Each cell is the state the rectangle is in for that stretch of time; every state is drawn below under “Every state, rendered”. The state machine is one pure function of elapsed time: none before 600 ms, quiet until 10 s, then explained (naming the host when one is still open), and settled the moment the page paints.

The thresholds, and why they are still proposed

AtWhat changesWhy this number
600 ms Quiet line appears Under Nielsen's 1 s flow limit, so the message is up before the user forms the question – and roughly twice an ordinary local open, so a fast page never flashes it.
10 s Escalates: names the host, offers Stop Nielsen's attention limit. We escalate before it, not after, because Erfana cannot offer an ETA – so the explanation has to already be on screen when patience runs out.
30 s Nothing new here The request filter already records network-timeout and the tab badge already counts it. Do not draw it twice.
Both numbers are chosen, not measured, which is exactly why this card is proposed and not decided. The rule – hold the rectangle, name who you are waiting for, never predict – is a contract. The milliseconds are a value still being chosen, and docs/design-system/README.md says values stay proposed however finished the card looks.

Where it lives, and why the page cannot reach it

The previewed page is a native view. It paints above all sibling DOM over its own rectangle, so you cannot put a spinner on top of it. That single fact rules out most designs and produces these two surfaces.

SurfaceWhereWhy the page cannot touch it
A – the message Inside the placeholder, the full rectangle It exists only before first paint, when the view is not on screen at all. A page that is not on screen cannot cover anything – the same reasoning the chrome gate already uses when it treats a hidden page as proving nothing.
B – the residual line A third slot in the band's existing bar The band is a flow sibling above the page's rectangle. The page has nowhere to paint that could reach it. Horizontal only – see the note in this card's CSS.
Contrast is only knowable on Surface A because of when it exists. Pre-paint the backdrop is provably the brand black, so the text is measured against it: the body text (--color-text-tertiary) is 8.52:1 and the quieter aside (--color-text-secondary) is 5.01:1, both clear of the 4.5:1 small text needs. The aside used to be --color-text-muted, at 3.63:1 – this card rendered a contrast failure in every case that showed it. If this surface were ever allowed to render over the page's own paper – which the page chooses – the contrast would be uncontrollable. That timing is a precondition of the design, not a detail of it.

Precedence: only one thing may own the rectangle

There are four ways a preview can show no page, and they must not blur together.

SituationWaiting message?Why
Loading, nothing painted Shown This is the case the card is for.
Band's list is open, page paused Suppressed Not a wait. A finished, deliberate Erfana action with a named cause and a known exit – collapse the list. Calling it "waiting" would suggest Erfana is stuck when it is not, and would bury the one instruction that ends it. It is also a security notice; diluting it into an ambient progress line is a loss.
Inactive tab showing its still frame Suppressed The frame already answers "what is here". A panel nobody is looking at has no wait to report, and its live region must stay silent.
Splitter or window-edge drag, page frozen Suppressed Not a wait: the page is being resized, and returns the moment the drag ends. The still picture holds the rectangle at its captured size, top-left – or the page's own paper when the picture is out of date – and stays until the page is confirmed back on screen. No text, no spinner, no "Resizing" label, nothing announced (issue #124, UX §4).

Accessibility

Reuse the band's live region. Do not add a second one. The band already mounts a role="status" node for the life of the panel, which is the mechanism the Feedback card marks correct.
RuleDecision
Politenesspolite at every stage, never assertive. A slow load is not an error.
How often it speaksAt most twice per load – once at the 10 s escalation, once when it ends. Nothing at 600 ms: that would fire on ordinary opens, and a region that speaks on every transition is a toast with extra steps.
FocusStop is a normal tab stop and is never auto-focused – taking focus out of the editor because a page is slow is hostile. When it unmounts while focused, focus moves to the band chip, the destination the band already uses.
Target sizeStop at --btn-height-md (32 px), matching the band's confirm buttons. It is reversible, so it does not need the "never the smallest target" treatment.
Wrapping and translationSurface A wraps at 56ch, absorbing 40 % expansion. Surface B must not wrap – wrapping grows the band, which pushes the page – so it ellipsis-clips rather than reflowing.
Host namesThrough the existing .erf-host primitive. Do not re-implement the bidi handling; the band's stylesheet records what happened last time.
Reduced motionNo animation at all – no spinner, no pulse, no progress bar. Case 9 below renders it, so "there is nothing here to disable" is falsifiable by clicking rather than a claim you have to trust.
Why no spinner, put plainly. A spinner says "working". It cannot say how long or on what, and those are the two questions the black rectangle provoked. Words say all three. Erfana also already carries three separate spin keyframes and none of them lives in the shared utilities stylesheet – a fourth would be walking away from where the Motion card is trying to go.
A bug this design creates unless it is handled. The panel currently swaps its ARIA role to img whenever the native view is hidden – which pre-paint is exactly when Surface A is up. That would make the whole subtree presentational and put the Stop button out of reach of a screen reader. It must stay group whenever Surface A is showing. Found by reading, not by testing; it needs a test.

Exceptions

None yet – nothing is built. The first deviation goes here with its /* deviates: … */ comment from the code, per docs/design-system/README.md.

What this card does not know

Open questionWhy it is not settled here
Does holding the view hidden throttle the page? Whether hiding a native view marks the document hidden and throttles it in this Electron version was not measured. Network fetches are not visibility-throttled and the app already hides previews on every tab switch, so the exposure looks small – but it must be measured before this card is promoted.
What counts as "can draw"? There is no first-paint event available, so the release signal has to be dom-ready, which is a lower bound on painting, not painting. A bare render-blocking stylesheet can still hold the page blank afterwards. Surface B exists because of that gap – it is the honest shape of the problem, not a patch over it.
