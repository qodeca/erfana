Commenting on selected text

Select a few words in a preview and comment on them. The comment is still stored on the element (HTML) or block (Markdown) that holds the words – so its place in the file, its pin and its thread work as they do today – and it also remembers the words, which stay underlined while they can be found. This card shows the HTML Preview, where selecting is new; the Markdown side is on the Markdown cards.

Proposed, and static. Plan: docs/designs/comments/selection-comments.md. No script: every state is drawn on its own. The previewed page is the HTML cards' fake page (third-party look, exempt from tokens). The underline is drawn as a span here; in the app it is boxes in the overlay's closed shadow root.

1 · select

In comment mode, drag selects

Today comment mode cancels the press that starts a selection. Now a press that moves 4 px or more selects text; a still click still opens the window on the element. Page scripts still never see the press.

The outline moves to the smallest element that holds the whole selection, labelled p.lede · selection. Announced: "Text selected in p.lede. Press ⇧F10 to comment." – the key as formatShortcut renders it on macOS; “Shift+F10” on Windows and Linux.

4 · saved

Pin on the element, words underlined

The pin is today's pin on the element's corner. The underline is one box per line of the selection (a wrapped selection gets two), drawn in the overlay – page scripts cannot see or remove it, Find never counts it, and printing hides it.

Two-tone like the outline: an accent fill and bar with an ink line under it, so it reads on white and black pages.

5 · select first

Or select, then turn on comment mode

With the mode off the page keeps its own mouse, so double-click and triple-click select words and lines. Turning the mode on with a selection skips the picker and opens the window on the words. Announced: "Comment mode on. Commenting on the selected text."

Works the same in the Markdown preview.
