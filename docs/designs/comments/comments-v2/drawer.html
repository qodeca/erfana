Comments v2 – the comments drawer

The drawer after the comments v2 review, in both previews. It keeps the decided drawer's shape – a flow sibling at the inline end, 320px wide, the Rows card's list – and changes what it groups, counts and says. Plan: docs/designs/comments/comments-v2.md (owner decisions §2, changes §3, removed-outside note §4.2).

Static. No script: each state is drawn on its own, as a standalone drawer in a fixed box. Where HTML and Markdown strings differ, both are drawn. Markdown uses the C-03 nouns – a kind and a line (“List item · line 14”), never a tag name, “element”, “page” or “block” – and says Show in preview where HTML says Show on page.

The drawer at rest

One row of three cells. The filter is three equal grid cells – Open, Resolved, Can't edit – kept on one row at the drawer's default width – a deliberate difference from the Segmented control card, which stacks these three labels below about 432px (an owner decision – see Exceptions). “Show” is no longer drawn; it stays the radio group's aria-label. Not found comments stay in Open with a neutral tag (OD-04): they usually mean the agent did what was asked. Changed is a neutral tag with an accent outline, never the warning look. The toolbar's icons toggle is gone; its job is the checkbox Show comment icons and underlines (C-20).

Resolved and Can't edit

Can't edit holds the comments Erfana can show but not change: damaged ones and ones in a newer format (OD-04). The ▲ badge is a shape, not a tint, and counts damaged comments only – the toolbar reads “7 comments ▲1” (R-14), with the Badges card's attention counter. A newer-format comment is not damaged, so it gets a neutral tag and no ▲. A click on a Can't edit row opens its read-only window; there is nothing in the preview to reveal.

Sort

A menu button in the header, “Sort: File order” by default (C-15). Changed is a tag plus a sort, not a fourth filter cell, so the filter stays three cells. The open menu is the Menu card's: one Tab stop, menuitemradio items, a check on the chosen one, hover and keyboard focus look the same.

A click opens the thread

Mouse and keys now differ on purpose (C-13). A mouse click anywhere on a row opens the thread: reveal plus the comment window. ↑ ↓ Home End move the active row and reveal only – Show on page in HTML, Show in preview in Markdown – and focus stays in the list, so a keyboard user can skim targets without a window opening on each step. The active row's Open stays its second Tab stop. Damaged, newer-format and not-found rows have nothing to reveal; the arrow keys only move the highlight, and a click opens their window.

Grouped by file (HTML)

One sticky heading per file (C-26). Frame rows no longer sit under the page's heading, and the “In frame:” tag is gone – the heading says it. In the windowed list the headings are virtual items with role="group" and aria-labelledby. Markdown has one file and keeps its plain file line.

Comments removed outside Erfana

A session-only note (OD-06, §4.2). When a re-read finds open threads gone and the file changed outside Erfana, an info note sits above the list, outside the scroll, so it stays in view. Show expands a read-only list – first message, author, target – with Copy text per thread. Nothing is written to the file; the note is gone after Dismiss or a restart. Info, not warning: removing a comment is often what the agent was asked to do.

Empty

The empty file teaches both gestures (C-16) – clicking and selecting – in each preview's own words. Each empty state is the States pattern's inline form – a title, then a hint. A filter with nothing in it says so plainly and its hint names where the other comments are, because the filter cells sit directly above (States pattern, frame 4); the other cells keep their counts so the way out is visible.

Unseen and last activity · later (P2)

C-24 is P2 – drawn so the row has room for it, not planned now. A per-user “seen” ledger in app data, never in the file. Unseen rows get the Badges card's unseen dot (.erf-badge--dot) before the label and a New tag before the author; the meta line shows the last activity, not the first message. The header gains Mark all as seen on a second header row at the default drawer width, rather than shortening the sort label. The dot is aria-hidden; “new” is read in the row's description.
