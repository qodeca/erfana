Comments v2 – the comment window

Every state the v2 plan adds to Erfana's comment window, in both previews. The window itself – size, head, body, foot, buttons, banners, field – is the decided comment window card; this card draws only what changes. Strings are exact, from docs/designs/comments/comments-v2.md.

Proposed, and static. No script: every state is drawn on its own as a role="group" example. Where the HTML and Markdown strings differ, both are drawn. Markdown strings use the C-03 nouns (paragraph, list item, H2 heading…) – never a tag name, “element”, “page” or “block” – and the stored thing is always a “comment”. Under each window, Description is what the window's accessible description reads (C-10: the context line, script note and quote are passed to ariaDescribedBy).
Two directions were weighed for the new parts. (A) put the quote, Narrow to words and Was/Now in the window head, under the context line, as the v1 Markdown card did; (B) keep the head to title, context and stepper, and open the body with them. B is drawn: the head never scrolls, so a 4-row field or two quote boxes there would squeeze the thread at the 560px cap, and the body already scrolls. For the rebuild confirmation, a danger box (the delete look) was rejected: rebuilding loses nothing, so it uses a neutral recessed box.

New comment – quote, blocked Save, saving (C-21)

The quote of the words is quieter than the comment: --text-base, --color-text-primary, the 2px accent rule kept, three lines then Show all. “Only the first 200 characters are kept” appears only when it is open. A blocked Save looks blocked – tertiary fill and label, a 1px edge – but its focus ring stays full strength. Saving keeps the accent and adds a 12px spinner.

Narrow to words – the keyboard route to selection comments (C-07)

Under the context line, a disclosure in the link colour. Open, it is a read-only 4-row field holding the target's text from main's own parse; Shift+arrows and Shift+Ctrl/Option+arrows select. A polite line under it says what the comment will be on, with a Whole {kind} text button that clears the selection. Opened from a mouse selection, it starts expanded with that range selected.

Threads – stepper, Resolve and next, all done (C-13, C-22)

The stepper sits in the head, right of the title: two 24px icon buttons around a mono --text-sm tertiary count. It steps through threads in file order within the drawer's current filter (default Open); keys Alt+F9 / Shift+Alt+F9. When another open thread exists, Resolve becomes Resolve and next; with text in the reply field, Reply and resolve does one write and one reload. Clicking an element that already has open threads opens them, with New comment first in the foot (C-22).

Not found – a possible success (C-05)

An info banner, not a warning: the agent may have done exactly what was asked. The reply box and Resolve stay; Resolve is the primary and takes focus. Delete lives only in the first message's … menu. The foot is one row. The context line names the state; a muted line says where the comment itself is, and Open in source goes there.

Changed since comment, and words changed (C-06)

Derived, never written to the file. An info banner, then Was (stored, struck through, tertiary) and Now (current text, first 200 characters) in the C-21 quote style. Resolve is the primary and takes focus; Reply and Close are secondary.

The file changed under an open window (C-14)

Text travels with the reader and never silently expires; lists and windows refresh on any change. A moved or expired draft keeps the window open with [Pick again] as the primary; the next new-comment window in that panel takes the text. A removed thread stays open read-only. A reply that hit a changed thread keeps its text and Reply stays enabled.

Refusals and validation – a reason and a next step (C-19)

The save answer carries a reason, and the window says it in one sentence with what to do next. Every refusal keeps the text. Field problems sit under the field and go to the window's assertive alert; counter crossings are announced once each in the polite region (“400 characters left”, “Over the limit by {n}”).

The folder refusal (“build, dependency or hidden folders”) is removed by OD-07 and is not drawn.

Unsaved source – compact banner actions (C-26)

Banner actions are part of the message, not the window's choices, so they use the compact .erf-comment-action (24px, --text-sm) in one row, primary first. The window keeps one heavy pair – Cancel and a blocked Save.

Damaged by hand – Rebuild from data (OD-05, §4.1)

Offered only for readable-mismatch or id-mismatch with a valid @data, and only when the user starts it. The banner gains a third action, Rebuild from data…, which opens an inline confirmation listing the lines that differ. Focus goes to Cancel; nothing is written until a choice.
