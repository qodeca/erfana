Comments v2 – overview

v2 makes commenting work the same way in the HTML Preview and the Markdown Preview, and fixes the weak spots six reviews found. In plain words: when you select words, a Comment button appears; the window quotes your words and lets you narrow them from the keyboard; a saved comment shows one mark that looks the same in both previews; you step through comments with ‹ › and resolve as you go; the Markdown side speaks plain words (paragraph, list item) and its window stays beside the text instead of covering it; and "not found" or "changed" now read as "the agent probably did it – check, then resolve".

Proposed, and static. Plan: docs/designs/comments/comments-v2.md – owner decisions OD-01…OD-08 (§2), changes C-01…C-27 (§3), owner-decision designs (§4). No script: every state is drawn on its own. The HTML page is the HTML cards' fake third-party page (exempt from tokens); the Markdown panel is the Preview-only view – comments never appear in split or editor view (OD-03).

The journey, in both previews

Select words → Comment button → window with the words and "Narrow to words" → save → comment mark and icon → click the mark → step with ‹ › and Resolve and next → "All open comments are resolved". The HTML window stays modal over a still image of the page; the Markdown window is non-modal and sits in the right margin when there is room (C-18).

1 · select

Select words – the Comment button appears

About 150 ms after the mouse is released over a selection, a Comment button appears 8px above the end of the selection's last line, at the proposed toolbar tool height (28px, Toolbar card) and with the Surfaces card's floating edge and shadow. It takes no focus, leaves the selection alone, and hides on Esc, scroll or collapse. HTML: only in comment mode, because outside it the page owns its mouse. Markdown: in and out of comment mode.

2 · write

The window quotes the words; "Narrow to words" waits, folded

The quote is quieter than the comment: body size, primary text, three lines then "Show all" (C-21) – system sans in HTML, the preview's serif in Markdown. Under it, the Narrow to words disclosure (C-07) opens a read-only copy of the target's text, the keyboard route to the same result. HTML: modal, over a still image of the page. Markdown: no modal, no catcher; with at least 376 px free right of the text column, the window sits in that margin, top-aligned with its paragraph, and the preview keeps scrolling (C-18).

3 · saved

One comment mark, and the icon on the target's corner

The same mark in both previews: the Text highlights card's comment mark – a 35% accent fill with a continuous accent bar under the text, never the selection colour and never a thin line that reads as a link (C-12). On a light HTML page the bar turns deep indigo, because the violet bar is under 3:1 on white (Text highlights card). The icon is unchanged in look; in HTML its layer is hidden from assistive tech, in Markdown it is a real button named "1 comment on paragraph, line 7. Open." (C-11).

4 · open and step

Click the mark – its thread opens with the stepper

A click on the mark opens that thread, its words in the active fill and its icon selected (C-17; in HTML only in comment mode, where the mark takes clicks like the icon). The head carries ‹ 3 of 12 ›: two Buttons-card icon buttons (24px) around a muted count, stepping through threads in file order within the drawer's filter, also on ⌥F9 / Alt+F9 (next) and ⇧⌥F9 / Alt+Shift+F9 (previous). While the stepper shows, the footer is one row – Close, then Resolve and next last – and Open in source and New comment move into the head's More actions menu (R-06, confirmed by the owner on 2026-10-28; the Dialog pattern's one footer row, primary last). Reply is blocked until there is text: the Buttons card's blocked look, aria-disabled with a reason (C-21).

5 · done

After the last one: all open comments are resolved

Resolving the last open thread folds it to one line and shows the end message; focus moves to Close. The stepper leaves the head, because nothing is left to step to. Same window in both previews; only the title and context follow each preview's naming (C-03).

HTML right-click outside comment mode (OD-01)

Outside comment mode, when the page did not cancel its own right-click, Erfana shows one item. Comment here… turns comment mode on with the picker on that element; with selected text on the page it reads Comment on selection. This changes shipped HTML §10.3: the page no longer owns every right-click.
