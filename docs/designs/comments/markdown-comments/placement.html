Where a Markdown comment is written

A comment block always takes lines of its own, before its target, with the same line prefix on every line. Most blocks take it right before their first line. Three places would change how the file renders, so Erfana never writes there. Lines with a lime edge are what Erfana inserts, lines with a red edge are where it never writes, and the bold line is the target. Blocks are shortened to their first and last line here – the real block carries the note to agents, the status, target and message lines, and @data.

Rules alone are not trusted. Every write is checked: main renders the file before and after with the preview's own pipeline and compares the two. If they differ, the next slot is tried; if none passes, the save is refused and the text stays in the window. Evidence: node docs/spikes/markdown-preview-comments/placement-check.mjs (plan §5.4).

Before the block

Paragraph, heading, code block, diagram, table, quote

Right before the target's first line, no prefix. The same for a whole list or a whole table.

## Launch plan<!-- erfana:comment v1 id=c-aaaaaaaaaaaaaacn…-->We ship the beta to the first ten customers.

same render

Directly after a heading

No blank line is needed or added: a comment line can start right under a heading.

## Launch plan<!-- erfana:comment v1 id=c-aaaaaaaaaaaaaacn…-->We ship the beta to the first ten customers.

same render

Lists

First item: before the whole list

The anchor names the item inside the list (li:nth-of-type(1)).

### Steps<!-- erfana:comment v1 id=c-aaaaaaaaaaaaaacn…-->- Freeze the API on Monday.- Run the load test against staging.

same render

Item 2 and later: end of the previous item

Indented to the previous item's content, so it stays inside that item and the list stays one list. A tight list stays tight.

- Freeze the API on Monday.  <!-- erfana:comment v1 id=c-aaaaaaaaaaaaaacn  …  -->- Run the load test against staging.

same render – bullet, ordered (indent 3), task list, loose list

Nested item

The same rule one level down, with that level's indent.

- Release  - Tag the build.    <!-- erfana:comment v1 id=c-aaaaaaaaaaaaaacn    …    -->  - Sign the installers.

same render

Never: before item 2 at column 0

The comment ends the list, so one list renders as two – and an ordered list restarts its numbers.

- Freeze the API on Monday.<!-- erfana:comment v1 id=c-aaaaaaaaaaaaaacn…-->- Run the load test against staging.

changed – <ul><li>a</li></ul><ul><li>b</li>…

Tables

Row or cell: before the whole table

The anchor names the row or cell inside it – the format's "comment is about <td> at … inside this element" form. The window says "Saved before the table on line 18."

<!-- erfana:comment v1 id=c-aaaaaaaaaaaaaacntarget: <table> (comment is about <tr> at tbody > tr:nth-of-type(2) …)-->| Owner | Task        | Due ||-------|-------------|-----|| Anna  | API freeze  | Mon || Piotr | Load test   | Wed |

same render

Never: between two rows

The table ends at the comment; the rows after it render as plain text.

| Owner | Task        | Due ||-------|-------------|-----|| Anna  | API freeze  | Mon |<!-- erfana:comment v1 id=c-aaaaaaaaaaaaaacn…-->| Piotr | Load test   | Wed |

changed – the last row becomes <p>| Piotr | …</p>

Block quotes and paragraphs

Inside a quote: the quote's prefix on every line

The format's ind grows from "leading blanks" to "line prefix". Its grammar does not change.

> Ship small.>> <!-- erfana:comment v1 id=c-aaaaaaaaaaaaaacn> …> -->> Ship often.

same render

Never: between two lines of one paragraph

The paragraph splits in two. A block only ever goes before a block's first line, so this slot is never offered; a selection in the middle of a paragraph targets the whole paragraph.

We ship the beta to the first ten customers,<!-- erfana:comment v1 id=c-aaaaaaaaaaaaaacn…-->after the security review.

changed – one <p> becomes two

Never written

PlaceWhy
Above or inside the frontmatterThe frontmatter must be the file's first lines; a comment above it turns it into text. The menu keeps its comment item, disabled with the reason "Comments can't be added to the frontmatter." (menu matrix M-18 – M-21).
Mid-lineMarkdown blocks own their lines; HTML's mid-line form is never used in .md.
Inside a code blockIt would be code, shown in the preview. A selection inside code targets the whole code block.
