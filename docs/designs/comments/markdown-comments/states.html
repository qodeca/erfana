Markdown comments – every state

The states the Markdown preview adds. Every state the HTML window, drawer and identity step already decide – counter, saving, delete confirmation, damaged block, identity errors – applies unchanged and is not repeated here: see the window, drawer and identity cards.

Static. No script: each state is drawn on its own. Plan: docs/designs/comments/markdown-preview-comments.md §9.

Toolbar, per view mode

The three tools follow Find, as in the HTML band: Comment mode (toggle), Comments (opens the drawer, carries the open count) and Show comment icons (toggle, per tab, not saved). They are the Buttons card's icon tools and toggles in the Toolbar card's row: a pressed toggle is fill plus the lime foot; the checked view mode is fill only (Toolbar card, view modes), so "a mode is on" never reads as "this view is chosen". The counts are the Badges card's .erf-counter and .erf-counter--attention. Comments work in Preview only (decision M11): Editor only and both split views show no comment tools, icons or underlines.
Differs from the cards, as shipped. The tools are 32 × 28 (the Toolbar card's square is 28 × 28) and the row sits on the panel's primary surface – both from MarkdownToolbar.css:72, :102. The row keeps one Tab stop per control, as the Markdown toolbar ships, not the Toolbar card's one stop with arrow keys (that card's open defect). See the Exceptions table.

Comment mode – outline, and the target in the mode tab

The picked block shows the Focus card's one ring, outside the block's box so it never covers text – never the two-tone ring, which is only for the HTML Preview overlay over a third-party page (owner decision, 2026-10-28). No floating label (Comments v2, C-21): a label above the outline covered the line above it. The mode tab names the target in the Writing card's kind nouns, with its source line from data-line-start – “Comment mode · List item, line 14 · Esc to leave”. Rows and cells name their table position, because their comment is saved before the table.

Icons (design name: pins)

The HTML pin, unchanged: same body, numbers and states (overlay card). The Markdown rule is only where it lands – the tail on the block's top-right corner, which for a full-width block is the content's right padding. Resolved, not-found and hidden pins are not drawn. The reader's word for a pin is icon (Writing card), so every accessible name says “comment”, never “pin”.

The phrase underline

Drawn with ::highlight(erf-comment) in the app – no DOM node, so export, copy and React re-renders never see it. The look is the Text highlights card's comment mark: the proposed --color-comment-mark fill (35% accent) and a --color-comment-mark-bar bar. The open thread's mark (erf-comment-active) keeps the same fill and doubles the bar – one active value, never a stronger fill. Accent, never Find's lime, and Find paints last. Never the only cue: the icon and the drawer row say the same thing. Hidden with the icons, and for resolved threads.

Menus

A disabled item says why. The decided Menu card keeps a disabled item reachable and places its reason on a visible second line inside the item (.erf-menu-desc), linked by aria-describedby – never a hover tooltip or a title, which a keyboard or touch user never sees.

The window – what Markdown adds

The window is the decided HTML window (comments.css). Its banners are the Feedback card's boxed .erf-banner, with the severity word read first by a screen reader but not shown (“Warning: ”, “Note: ”) and actions as erf-button--secondary erf-button--sm. The info tone reads the proposed --color-info-bg and --color-info-border through the card's fallback. The shipped CommentBanner (CommentParts.tsx:89-110) has no spoken severity word – the Feedback card's open defect; this screen draws the target, not the shipped markup. Names follow the Writing card: “List item · plan.md, line 14”, never a tag name.

Drawer

The HTML drawer, beside the preview – never over the editor in split view. Rows carry the Markdown kind noun and line and, when the comment was made on a selection, the phrase in quotes. The rows are the HTML drawer's, which the Row card lists in its Exceptions; the Drawer pattern and the Segmented control card are where the shell and the filter are heading (Comments v2).
