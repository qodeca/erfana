Markdown comments – every state

The states the Markdown preview adds. Every state the HTML window, drawer and identity step already decide – counter, saving, delete confirmation, damaged block, identity errors – applies unchanged and is not repeated here: see the window, drawer and identity cards.

Static. No script: each state is drawn on its own. Plan: docs/designs/comments/markdown-preview-comments.md §9.

Toolbar, per view mode

The three tools follow Find, as in the HTML band: Comment mode (toggle), Comments (opens the drawer, carries the open count) and Show comment icons (toggle, per tab, not saved). The toggles use the HTML band's signature – fill and a 2px lime foot – not the view-mode fill, so "a mode is on" never reads as "this view is chosen". Comments work in Preview only (decision M11): Editor only and both split views show no comment tools, pins or underlines.

Comment mode – outline and label, per block kind

The HTML two-tone ring on the block's box, grown outward by the ring so it never covers text. The label is kind · source line, from the block's data-line-start. Rows and cells name their table position, because their comment is saved before the table.

Pins

The HTML pin, unchanged: same body, numbers and states (overlay card). The Markdown rule is only where it lands – the tail on the block's top-right corner, which for a full-width block is the content's right padding. Resolved, not-found and hidden pins are not drawn.

The phrase underline

Drawn with ::highlight(erf-comment) in the app – no DOM node, so export, copy and React re-renders never see it. Accent, never Find's lime. Never the only cue: the pin and the drawer row say the same thing. Hidden with the pins, and for resolved threads.
