Commenting in the Markdown preview

The HTML Preview's comments, on a Markdown file. A reviewer selects a few words – or turns on comment mode and picks a whole block – and leaves a comment. Erfana writes the same erfana:comment v1 block into the .md file, on its own lines, before that block. The preview hides it; a pin and an underline show it. Everything a comment looks like is the HTML feature, reused unchanged. This card shows only where it lands in the Markdown panel.

Proposed, and static. Plan: docs/designs/comments/markdown-preview-comments.md. These cards carry no script, so every state is drawn on its own and nothing here can be clicked through. The window and drawer come from ../html-comments/comments.css; the pin, outline and mode frame from ../html-comments/overlay.css. The toolbar is the Toolbar card's row with the Buttons card's icon tools and toggles, the count is the Badges card's counter, and the underline uses the Text highlights card's names and values. Only the Markdown panel mirror and what the Markdown toolbar keeps of its own are in markdown-comments.css.
Where this screen differs from a card, and why.
  • Tool size – Buttons and Toolbar. The Markdown toolbar's icon tools are 32 × 28, not the card's 28 × 28 square, and the row sits on the panel's primary surface. Both ship that way (MarkdownToolbar.css:72, :102); the comment tools match their row. The Buttons card's Exceptions row records the size.
  • Keyboard – Toolbar. The Markdown toolbar keeps one Tab stop per control, as it ships, with no roving tabindex and no arrow keys. The Toolbar card asks for one stop and arrows, and lists this toolbar as an open defect. The comment tools follow their row; they add no keys of their own.
  • Every state – toolbar per view mode, outline labels per block kind, pins, underline, menus, window and drawer.
  • Where the block goes in the file – the slot for each kind of block, and the three places Erfana never writes.
  • HTML Preview comments – the decided cards this one reuses: window, drawer, identity, toolbar, overlay.

5 · comment mode

Pick a whole block

⌥⌘M / Ctrl+Alt+M or the toggle. The HTML mode frame, and the picked block in the one focus ring (never the HTML overlay's two-tone ring). There is no floating label: the mode tab names the target and its source line – Comment mode · Row 2, line 21 · Esc to leave – so nothing is drawn over the text (Comments v2, C-21). Click opens the window; right-click opens a one-item menu; Tab and ⌥↑ / Alt+↑, ⌥↓ / Alt+↓ move between targets in source order.

A table row cannot carry a comment block of its own, so this comment is saved before the table and names the row inside it. The window says "Saved before the table on line 18."

Exceptions

WhereThe systemHere, and why
Overlay parts inside the block The overlay draws outside .markdown-preview-content (plan §7.1, M7). A static card cannot measure, so the icon and outline are children of their block with the same geometry. The shipping overlay is a sibling of the content, so export never sees it.
Underline as a span Shipping uses ::highlight(erf-comment) – no DOM node. A static card cannot call CSS.highlights; .erf-mdc-mark draws the same look.
Fixed positions of the menu and window Placed by measurement: right of the block, then left, below, above. Inline style offsets stand in for the measured placement in each frame.
