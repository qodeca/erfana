Comment tools in the toolbar

Two tools join the preview band after Find, because they act on this page: Comment mode and the Comments list. Show comment icons is the drawer's checkbox “Show comment icons and underlines”, not a tool in the row.

Built from the decided Permission band card. Same 32 × 28 tools, same inset ring, same aria-disabled rule (the dim goes on the icon, never the button), and the link toggle's pressed signature – a fill plus a 2px lime edge along the bottom – for every “on”: Comment mode pressed, the drawer open. A shape appears, so a state is never colour alone (SC 1.4.1). The icons are the registry's lucide message-square-plus and messages-square (plan §3), drawn from the registry by data-icon. Shipped in v0.23.1 and decided; the readout under “Narrow panels” compares the tier thresholds nav.css ships with what each row measures with the comment tools.
Owner decision, 2026-10-31: preview toolbars are icons only. The Comments list is the messages-square icon plus the open count when above 0, at every width, with no words and no narrow form. The ▲ attention counter sits beside the number. It carries a tooltip equal to its accessible name (“7 comments, 1 damaged”; “Comments” when zero), because the tool shows no words. The Markdown toolbar uses the same tool, the same pressed look and the same inset focus ring, and an 8px gap comes before the comment tools in both. The permission chip keeps its text.
Tooltips and shortcuts. The band's tooltips are the native title until it adopts the proposed Tooltip card's tooltip.css. That card's rule – a tooltip describes, it never repeats the name – is drawn here: a title that only repeats the accessible name is left out (Open in default browser, Export to PDF). The app still sets them (PreviewToolbarTools.tsx:124 and :187), so a pointer user sees the name twice – a Tooltip card defect, not a design choice. The Comments list is exempt: it shows no words, so its title is its name (owner decision, 2026-10-31; this withdraws the rule for this tool). Shortcuts follow the Writing card and the frames draw macOS: “Comment mode (⌥⌘M)”, “Find (⌘F)”, “Back (⌘[)”. The shipping copy still spells out “Cmd+Option+M” (commentModeShortcutLabel in commentCopy.ts) and “Cmd+[” (backTooltip in PreviewNavControls.tsx) – the Writing card's open defect.

The row

How the row is used. The frame below is the row at rest. Comment mode turns on from its tool or from ⌥⌘M / Ctrl+Alt+M – matched on the typed key m, never the physical key, because AltGr+M types µ on a German layout. The page gets its frame and tab, and the band's live region speaks (the states below draw each one). The accessible name of the toggle never changes; its state is aria-pressed. Esc with focus in the page leaves the mode – it is the second step of the existing Escape order: an open window first, then comment mode, then “return to chip”.

Unavailable

When a page cannot take comments, Comment mode is aria-disabled – it keeps focus and its tooltip, and the tooltip says why. The list stays usable when the file's comments can still be read (a link, a conflicted file – read-only, but readable); it takes the same state, and the same tooltip, when nothing can be read. Narrow panels: re-measured with the new tools

The band never wraps and never changes height; it steps down by container query (decided Permission band card). The thresholds in nav.css are read below by probing the shipping stylesheet, not typed. The Comments list looks the same in every tier: only other tools leave the row. A narrow tier sits between compact and minimal: there Export to PDF leaves (⌘S / Ctrl+S still exports), while Find stays. The narrow row fits the editor area's 400px minimum, so Find is on the row at every width the editor can have; it leaves only in the minimal tier, below that. Comment mode and the list stay in every tier: Comment mode has a shortcut but is the feature's front door, and the list is the keyboard route to every thread (it has no shortcut; Find has ⌘F / Ctrl+F).
nav.css today: compact below 534px, narrow below 446px, minimal below 378px. Measured in a browser on 2026-10-31 with the two tools and “12 ▲1”: the full, compact and narrow rows each fit down to their own threshold, and the minimal row needs 351px; below that it scrolls sideways.
