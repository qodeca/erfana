Comment tools in the toolbar

Three tools join the preview band after Find, because they act on this page: Comment mode, the Comments list and Show comment icons.

Built from the decided Permission band card. Same 32 × 28 tools, same inset ring, same aria-disabled rule (the dim goes on the icon, never the button), and the link toggle's pressed signature – a fill plus a 2px lime edge along the bottom – for every “on”: Comment mode pressed, the drawer open, icons shown. A shape appears, so a state is never colour alone (SC 1.4.1). The icons are the registry's lucide message-square-plus, messages-square and message-square / message-square-off (plan §3). Proposed: the plan files these cards as proposed (§10.11), and the narrow tiers below need re-measuring in nav.css before P6 ships.

The row

How the row is used. The frame below is the row at rest. Comment mode turns on from its tool or from Ctrl+Alt+M (Cmd+Option+M on macOS) – matched on the typed key m, never the physical key, because AltGr+M types µ on a German layout. The page gets its frame and tab, and the band's live region speaks (the states below draw each one). The accessible name of the toggle never changes; its state is aria-pressed. Esc with focus in the page leaves the mode – it is the second step of the existing Escape order: an open window first, then comment mode, then “return to chip”.

Unavailable

When a page cannot take comments, Comment mode is aria-disabled – it keeps focus and its tooltip, and the tooltip says why. The list and the pins tool stay usable when the file's comments can still be read (a link, a conflicted file – read-only, but readable); they take the same state when nothing can be read. Narrow panels: re-measured with the new tools

The band never wraps and never changes height; it steps down by container query (decided Permission band card). Three more tools make every tier wider, so the thresholds in nav.css – read below by probing the shipping stylesheet, not typed – no longer match what each row needs. The comment tools give way before Find. A new narrow tier sits between compact and minimal: there Show comment icons leaves the row – it stays reachable from the drawer's checkbox – and Export to PDF with it (Cmd/Ctrl+S still exports), while Find stays. The narrow row fits the editor area's 400px minimum, so Find is on the row at every width the editor can have; it leaves only in the minimal tier, below that. Comment mode and the list stay in every tier: Comment mode has a shortcut but is the feature's front door, and the list is the keyboard route to every thread (it has no shortcut; Find has Cmd/Ctrl+F).
nav.css today: compact below 534px, narrow below 446px, minimal below 378px. With the comment tools, measured in a browser on 2026-10-28 (re-measure in the inspector before changing nav.css): full row needs 539px, compact row needs 446px, narrow row needs 378px, minimal row needs 344px. Each threshold should become the need of the tier above it.
