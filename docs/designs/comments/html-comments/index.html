Commenting on a page

A reviewer turns on comment mode, right-clicks an element, writes, saves. Erfana writes the comment into the HTML file just before that element, reloads the page where it was, and shows a speech-bubble pin. Coding agents read the comments straight from the file. This card walks the whole journey; the five cards below hold every state.

  • Comment overlay in the page – outline, label, pin, mode frame and tab, and the token mapping the page receives.
  • Comment window – new comment, thread, edit, delete, damaged, read-only, not found, not visible, saving, every error.
  • Comments drawer – Open / Resolved / Needs attention, empty, loading, error, narrow.
  • Who is commenting – the one-time privacy notice, the identity step, Settings › Comments.
  • Comment tools in the toolbar – the three tools, the unavailable reasons, the re-measured tiers.
The line this design draws. Hover outlines and pins are drawn inside the page, in a closed shadow root, and carry no comment text and no emails – only counts. The menu, the comment window and everything you type are Erfana's own chrome, drawn while the page is frozen to a still image (decision 4). A page can fake an outline; it cannot see, style or type into the window where the words are.

Status. Proposed, as the plan files the set (§10.11). What the plan locks is not re-opened by any of these cards: Erfana draws the menu and the window over a still; the pin is a speech bubble at the element's top-right, one numbered pin for several threads, hidden when all are resolved; pins are always visible and can be hidden per tab; anyone may edit or delete any comment; name required, email optional, privacy notice once.

The keyboard and mouse contract

The page is a set of still frames – nothing on it responds to a click or a key. The steps below draw each state; this table says how the app gets from one to the next.

Before your first comment

button.cta · index.html, line 42

Erfana writes your name – and your email, if you add one – into the HTML file next to each comment. Anyone who can open the file can read them: in Erfana, in the page source, and in git history once the file is committed and pushed. Scripts in pages previewed in this project can read them too. Deleting a comment later does not remove it from git history.

STEP 07

Reopen from the pin

A pin opens its thread in any mode. Reply, resolve, edit or delete – anyone may change any comment (decision 31). Resolving hides the pin; the thread stays in the drawer under Resolved.

What it deliberately does not do

Not thisWhy
A “Send to agent” buttonAgents read the file; the comment is already where they look (decision 9).
Other menu itemsThe menu holds exactly “Add comment” in v1 (decision 14). Outside comment mode the page keeps its own right-click.
Rich textPlain text is what an agent reads unambiguously and what a diff shows honestly.
Animate anythingThe window and drawer open instantly; pins never move; the “flash” is a static highlight. Nothing to turn off under reduced motion, and nothing racing the native page.
Show a verified authorNames are typed, not proven. No badge, no avatar; git history is the audit trail.
