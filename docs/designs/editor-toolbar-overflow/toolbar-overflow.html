Markdown and Mermaid toolbar overflow

proposed not yet reviewed

The editor's Markdown toolbar and every Mermaid diagram's toolbar apply the Toolbar overflow card (decided) unchanged: buttons that do not fit move into a … menu, rightmost first, and nothing is cut off (#461). This screen decides no system rule; it draws how the card lands on toolbars that carry separators, a spacer, a live status region, a view-mode group and the comment tools.

Every state

What the frames show

  • A separator moves with the button after it. In the row a separator never leads or trails; in the menu one separates two groups that came from different groups of the row (a row separator, or the spacer), and is never first, last or doubled.
  • Pinned, never moved: the comment tools, the modified dot and the live status region. They count in the row's width, so the buttons beside them give way. The comment tools are a recorded exception to the card's rule 4; the live region must stay mounted (WCAG 2.2 4.1.3).
  • View modes and directions are toggles in the row (aria-pressed, the existing fill and lime foot) and checked items in the menu – a recorded exception to rule 7, which asks for a menuitemradio the shared menu does not have yet.
  • The spacer takes the leftover width and counts at its minimum when the row measures.

Exceptions

None on this screen. The two exceptions the build takes are recorded on the Toolbar overflow card.
