Feature designs / Project tree toolbar icons

Project tree toolbar icons

decided owner approved 2026-11-03 · design note README.md · issue #452

Four controls at the top of the Project panel show an icon that does not say what they do. This screen draws each one as it ships beside two or three lucide options, at the app's real scale, and marks one pick per control. Decided (owner, 2026-11-03 – every recommendation below): Import becomes file-input (an arrow going into a file), Import-while-busy shows the system's busy ring instead of Refresh's arrows, and the file filter becomes a labelled one-of-two choice whose active side is visible even when its panel is closed.

What ships, and where. Import and Refresh are in the tree toolbar row (ProjectTree.tsx, .project-tree-actions). The two filter buttons are not in that row: they sit in a “File Filter” panel that opens from a chevron in the Project panel header (ProjectPanel.tsx, .control-panel-chevron). With that panel closed, nothing on screen says Markdown only is on – the only trace is a tree with fewer files in it. The chevron is also a <span> with a click handler and a title: no role, no tab stop, no name. Every other button in the row stays exactly as it is; the frames draw them quieter so the eye lands on the control being decided.

The top of the panel, before and after

A project is open and Markdown only is on. Panel header above, tree toolbar row below, a few rows under it. Drawn at the shipping sizes: 41px rows, 24px buttons, the size={14} glyph at lucide's default stroke.

1 · Import a file – idle

Each option drawn in its place between New folder and Refresh, then alone in every state the shipping .icon-btn has. The neighbours are context and do not change.

2 · Import a file – while busy

Each frame draws Import busy beside Refresh at rest, then both busy at once – the case where today they are the same picture. A frame is still; the caption says what turns. Under reduced motion nothing turns (ProjectTree.css already stops .spin), so the still shape alone must tell them apart.

3 and 4 · Show all files / Show only Markdown files

The issue is two problems, and an icon fixes only half of one. “Is this a filter?” is answered by the control's shape and its words; “which one is on?” by a checked state that is not colour alone, and by a trace that survives closing the panel. So this section draws three ways to show the filter, then the icon options for each of the two choices.

Exceptions

None recorded.

Cards it builds on

  • Icons (proposed) – lucide glyphs as data-icon; a new glyph joins the registry before it is used. The card's size and stroke rules are a separate change, so every frame here draws the shipping 14px and stroke.
  • Buttons (proposed) – the busy ring, the pressed signature, aria-busy with aria-disabled.
  • Segmented control (proposed) – the filter choice and its keyboard.
  • Badges, chips and keys (proposed) – the outline chip for “Markdown only”.
  • Toolbar (proposed) – the row itself, unchanged here.
  • Motion (proposed) – one spinner, and nothing turns under reduced motion.
