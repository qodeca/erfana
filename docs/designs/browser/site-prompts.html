Site prompts

proposed not yet reviewed · design note README.md · spec 025 v0.11.0

Every request a site makes of the reviewer, for spec 025’s browser tab: permission prompts and the in-use chip, the full-screen and pointer-lock notices, the popup origin strip, download notices, the sign-in box and the page’s own dialogs. One sentence covers them all: the site asks in the strip – a row above the page, starting with the origin Erfana read from the engine. One static frame per state, drawn to scale with the system’s CSS. Build nothing from it until the owner approves it (025-FR-043).

How to read a frame. Every drawing is a picture (inert, aria-hidden); the caption names the surface and state, the spec ids, and – where the drawing follows an open decision the owner answered on 2026-11-01 – “Owner decision OD-n” or “SPEC-n”; “Assumption” marks a call no one has answered yet. Frames are macOS unless tagged Windows or Linux. The white and the dark pages are third-party content (.ds-foreign-page), not Erfana. A menu or dialog that crosses into the page area is drawn over a still image of the page: it looks identical, and that is the point – nothing over it is the page’s.
Cards cited. New and proposed with this design: Site prompts (every strip row), Origin field (the field, its chips and the read-only popup strip), Element picker (the pick frame). Decided: Permission band (chrome is a flow sibling above the page), Form controls (sign-in fields, checkboxes, the disabled reason), Focus and keyboard, Rows and lists (origins wrap, never cut). Proposed: Feedback (toasts, boxed banner, hidden severity word), Buttons (secondary, blocked, busy), Dialog (not used – page dialogs stay in the strip, OD-8), Writing.

Permission prompt and in-use indicator

Site prompts card, permission kind. Every row starts with the requesting origin drawn by Erfana from the engine, then the request in Erfana’s words. It never takes focus; the page keeps its violet ring. Answers are secondary buttons, so none is nudged.

Fullscreen and pointer-lock notice

Full screen fills the page area, not the window (OD-4), so the rows that state the origin never leave. The notice is a 4 s strip row, with no buttons (025-FR-019). No frame shows full screen during pick mode: in pick mode the page receives no click or key, so it cannot get the user gesture full screen needs (M-18, recorded for ADR 0011); the notice therefore never shares the screen with the pick banner.

Popup origin strip

A pop-up window (025-FR-011) is drawn with the OS title bar as a plain stand-in (the OS draws it), then Erfana’s read-only popup origin strip, then the find row when open, then its own strip rows and page. Find and zoom act on the popup (025-FR-014).

Download notice

Finished and failed downloads are toasts (Feedback card), placed clear of the live view; several files at once is a strip row.

Sign-in box

The form kind of strip row: “Sign in to {host}”, Username, Password, Remember for this project, Cancel, Sign in. Warning and error lines are the Feedback card’s boxed banner inside the row. No server-supplied realm text is ever shown.

Page dialogs and leave-page prompt

A page’s own alert, confirm and prompt sit in the strip like every other site request (OD-8), in a look no other row shares: “Message from the page” over a dashed quote, the answers under it, no leading icon, and “Answer to the page” on a prompt() field. The header is Erfana’s. A dialog takes focus only when its tab is active and focus is already in the page (H-06).

Exceptions

None recorded. The screen source chooser is drawn as a strip form row because the note gives its strings but no place (listed as an assumption in its caption). Toasts sit beside the browser tab, over a terminal stand-in, because toastPlacement moves them clear of a live view.
