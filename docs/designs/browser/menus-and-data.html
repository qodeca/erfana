Menus and data

proposed not yet reviewed · design note README.md · spec 025 v0.12.0

The page right-click menu, the Clear browsing data and Forget dialogs, and the Linux keyring notices, for spec 025’s browser tab. The menu is Erfana’s, drawn over a still image so the page can never cover it; the data dialogs act on this project only and say exactly what they remove. One static frame per state, drawn to scale with the system’s CSS. Build nothing from it until the owner approves it (025-FR-043).

How to read a frame. Every drawing is a picture (inert, aria-hidden); the caption names the surface and state, the spec ids, and – where the drawing follows an open decision the owner answered on 2026-11-01 – “Owner decision OD-n” or “SPEC-n”; “Assumption” marks a call no one has answered yet. Frames are macOS unless tagged Windows or Linux. The white and the dark pages are third-party content (.ds-foreign-page), not Erfana. A menu or dialog that crosses into the page area is drawn over a still image of the page: it looks identical, and that is the point – nothing over it is the page’s.
Cards cited. Decided: Menu (the whole contract, the reason line, shortcut hints), Form controls (checkboxes and descriptions), Focus and keyboard. Proposed: Dialog (centred dialog, destructive confirm), Buttons (danger, blocked, busy), Feedback (toasts, note band), Layering (the still image), Writing.

Page right-click menu

Menu card, over the still image, at the pointer – or at the focused element from the keyboard. Items appear only when they apply.

Clear-data dialog and Forget

Dialog card, centred, with the dialog scrim. Cancel is focused on open in both; the act is the danger button.

Other toasts the spec requires

Error toasts with copy in the note’s § Other toasts the spec requires, placed clear of any live view (here no browser view is open).

Linux keyring notice and keyring reset

Note bands in the strip (Feedback card band form), Linux only. Dismissed once, the weak-protection notice never returns in that project; until then it shows on each start.

Exceptions

None recorded. The dialog scrim is drawn inside the frame (absolute, not fixed) so it covers only the drawing; in the app it covers the window.
