GitHub presentation

The README banner, the wordmark and the repository's social preview. This page is their source: npm run docs:brand screenshots the three pieces of artwork below at 2× into docs/assets/readme/, so a token change is one re-run away from a new banner, and no image editor holds a second copy of the brand.

The brand rules live on the Brand card (proposed): the icon used as it ships, the wordmark in Cascadia Mono bold, no third-party name or mark, flat and square, and indigo – never lime or violet – as the accent on a light surface. This screen does not restate them; it decides only the banner geometry: the two canvases (800×200 and 640×320 layout), where the lockup and the abstract window sit on them, the social card's safe area, and the image-scale sizes recorded under Exceptions.

The dashed outline around each piece of artwork is page furniture, not artwork: it marks the canvas edge, which is meant to disappear against GitHub's page, and it is never in the exported PNG.

Banner – dark

Shown by GitHub's dark themes through <picture> with prefers-color-scheme: dark. 800×200 layout, exported at 1600×400.

Banner – light

Shown by GitHub's light theme, and the fallback <img> for any viewer that does not honour <picture>. Same geometry; indigo replaces violet for the accent, as Brand requires on a light surface.

Social preview

The card link sites draw for github.com/qodeca/erfana. 640×320 layout, exported at 1280×640 (GitHub's recommended size); content stays inside the 1200×560 safe area. Dark only – it is not theme-aware. Uploaded by hand in Settings after the README merges.

Safe area

Sites that show the social card may crop its edges, so the lockup, the pitch and the window stay inside a 1200×560 safe area – a 40px margin on the exported image, 20px on the layout. The card's own padding is wider than that, so nothing reaches the margin.

Every ratio is baked from the tokens. Text is judged against 4.5:1; the cursor, the light banner's indigo nodes and edge, and the lime and violet rows against the 3:1 a non-text mark needs. Frames, pane bars and the selected line are decorative and carry no meaning; the README says in text everything the banner shows. The full brand set is on Brand – brand colours and their contrast.

What it deliberately does not do

Not thisWhy
A screenshot in the bannerThe demo loop below the banner is the real app. A second, static picture of it would compete and go stale.
An SVG bannerAn SVG inside <img> cannot load a web font; outlined text would make the source uneditable.
Transparent backgroundsA viewer that ignores <picture> would show the dark wordmark on a dark page.
A command name in the terminal stripIt would put a third-party name into Erfana's own brand image.

Exceptions

WhereDeviates fromWhy
.gp-art--light on this screenTheme – Erfana is dark-onlyGitHub has a light theme, and the banner is a page asset on github.com, not app chrome. The app rule does not change.
.gp-banner, .gp-social on this screenType – the UI type scaleThe icon (88px) and the wordmark (60px, 38px in the social card) are drawn at image scale, which the UI scale does not reach.
.gp-wordmark on this screenType – no letter-spacing tokenThe wordmark is tracked -0.02em so the bold mono name sits as one mark at 60px. The type scale has no tracking token, and the UI never tracks text; this is a value of the image, not of the app.
Every gp- class and #gp-* id on this screenNaming – the erf- namespace (docs/design-system/README.md, .stylelintrc.json)The namespace guards component CSS that moves into src/, where a bare class can collide with Mermaid's. This artwork never ships as CSS; it is rendered to PNG by scripts/capture/brand.mjs, which, with its test, reads the #gp-* ids.
