## QG-8 – U1: a keyboard route into the page (as built)

**Not in the design.** Neither the parent nor the part documents specified how a keyboard reaches the previewed page. The QG-8 UX audit found it cannot: the page lives in a native `WebContentsView` over a DOM placeholder, nothing called `webContents.focus()` (only `isFocused()` was read), and the placeholder was not focusable. So a keyboard-only reader could not follow a link in the page – part 3's headline capability – and none of the forwarded accelerators (Cmd/Ctrl+F, the export key, Cmd/Ctrl+W, Escape, Back and Forward) could fire, since each needs focus inside the page already (WCAG 2.1.1, level A). The way back out (Escape to the permission chip) already existed; the way in was added here.

- **Channel.** `preview:focusPage` (`PreviewChannels.FOCUS_PAGE`), handler `src/main/ipc/preview/focus-handlers.ts`, registered in `preview-handlers.ts` beside `navigate`. Same order as `navigation-handlers.ts`: `isTrustedSender` before the payload is read, then `PreviewPanelRequestSchema` (reused – it is exactly a strict, bounded `panelId`; `preview-schema.ts` stays at its size), then the sender's window. The answer is `{ ok: boolean }` (`PreviewFocusPageResult`), with no error code: every refusal means "no page to enter", and the renderer leaves focus where it is.
- **Service.** `previewViewFocus.ts` (a function the service hands on as `focusPage`, the `previewViewNavigation` split, because `PreviewViewService.ts` is near its cap) refuses no live view and another window's view; `PreviewLiveView.focusPage()` refuses a defunct view or one that is not drawn (`visibility.isWanted()`), then calls `webContents.focus()`. `focus` is optional on `PreviewWebContentsHandle`, like `ipc`, so older test doubles stay valid.
- **Renderer.** The placeholder is the target – no new visible control. `usePreviewPageEntry` (hooks) makes it focusable (`tabIndex=0`, role `button`) only while the tab is active (`api.isActive` via `onDidActiveChange` – the panel-scoped-globals rule) AND a page is live and drawn (normal view, load state past `idle` and not `suspended`, view not hidden). Enter or Space calls the bridge; nothing else does, so focus never moves on its own. Its accessible name comes from `previewPlaceholderLabel`: `HTML preview of <page> – press Enter to enter the page, Escape to come back`; otherwise the old `HTML preview of <page>`, which the e2e POM now matches either way (`placeholder()`).
- **Tests.** `focus-handlers.test.ts` (gate before parse, payload bounds, no window, service refusal, a throw logged redacted, dispose), `previewViewFocus.test.ts` (no view, other window, view refusal), `PreviewViewService.focus.test.ts` (over the navigation harness, which gained a `focus` spy: live, hidden, shown again, other window, unknown, closed, suspended), `HtmlPreviewPanel.pageEntry.test.tsx` (tab order and name, Enter, Space, no focus on its own, other keys, inactive tab, not yet running, hidden) – three of those failed before the change – `htmlPreview.logic.test.ts` (the label). `HtmlPreviewPanel.test.tsx`'s drag-freeze case now expects `button` where it expected `group`.
