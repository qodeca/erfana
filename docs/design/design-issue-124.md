## 1. Approach summary

- **Part 1 – the page never covers Erfana.** Every dropped bounds update is logged with its reason. The three suspected causes (position-only moves, a collapsed panel, zoom from the wrong window) are reproduced in a time-box and fixed only if reproduced. During a splitter or window-edge drag the live page is hidden and its still picture shown; it returns at the settled rect on release, through one release step that respects anything else covering the page. The picture goes out of date only on real input (scrolling, keys, clicks, touch), never because a pointer passed over it.
- **Part 2 – frames work inside the project.** `frame-ancestors` leaves the policy and `frame-src` names only the view's own token. A request-kind ledger built from `webRequest` replaces the header read that never worked (answer 5). Per-page state lives in one page scope. While main loads another page, a pending scope takes only that page's main-document refusal; the switch happens when the new page commits, and a load that never commits – replaced, or stopped without a commit (S15) – leaves the old page as it was. A refused frame is listed in the failure badge by whichever layer sees it: the frame guard (depth, count), the request filter, or – for frames the browser's own CSP refuses before any event (S10) – a failed-load writer. Blocked hosts inside frames reach the permission band through main-side console parsing; a refused frame never does. `srcdoc` frames cannot be stopped before they load (S11); past a cap they are shown and listed once (answer 9).
- **Part 3 – links can open in the same tab.** Main decides where a link may go (`same-tab`, `new-tab` or `by-mode`); the renderer applies the tab's mode. Main checks a move before anything happens, the renderer then resolves the other tabs (asking about unsaved edits), main commits the load, and only then do the other tabs close. The tab's `params.filePath` follows the page, so title, lookup and crash recovery read one value. Each tab has its own history in main, which survives sleep; an entry whose page was deleted is dropped on the first step that reaches it.
- **Part 4 – open in default browser.** A new sender-gated `browser:openFile` channel checks confinement on the real path and launches the real browser: `open -a` on macOS, the browser's executable on Windows. When the browser cannot be found, it falls back to the `.html` app and shows a notice.
- **Refactor first.** The files the feature must grow are split before any behaviour changes, each new module owning its own state (§3).

## 2. Technical decisions made here

| Question | Decision | Rejected, and why |
|---|---|---|
| Who routes a link | main returns `same-tab`, `new-tab` or `by-mode`; the renderer applies its mode, the tab rule and the prompt; main re-checks and loads in place | a main copy of the mode: three stores and a channel for one table row (RA7) |
| How a move runs | `preview:navigate` is an invoke with `phase: 'check' \| 'commit'`: check → resolve the other tabs → commit → close them | close first: tabs and edits are gone when main then refuses (RS4) |
| How a tab changes page | the same `WebContentsView` loads the new page; the panel id stays; `params.filePath` is updated on every `pageChanged` | close and reopen: loses history and zoom, flashes |
| Tab identity | lookup by `params.filePath` (`pathsEqual`); new ids get the smallest free variant | a separate current-page store: a second source that a crash remount forgets (RS3) |
| History | own list per panel in main, authoritative on resume; native step (`goToIndex`) only when the neighbour URL matches; a missing entry is dropped when a step reaches it; an in-page step pushes only after a real gesture – `takeRecentGesture()` in `previewStillFrameFreshness.ts`, `HISTORY_GESTURE_WINDOW_MS` 1 s, spent by every read – else replaces (QG-7 S1, QG-8 T1) | Chromium only: records frame navigations, dies with the token on sleep (S4, S6) |
| Per-page state | one page scope per page; a pending scope while main loads another page, committed on a main-frame `did-navigate` for the target's document (`samePreviewDocument`), dropped when the load is replaced or stops without a commit (RA2-1, part 2 §2.3) | a swap at load start: wipes A's badge and watchers when the load never commits; a swap at commit: loses the main-document refusal; ending on a fail event or by exact URL: a refused or superseded load fires none, and Chromium re-encodes a raw fragment (S15); ending on the load's promise or `did-finish-load`: neither is a commit signal (S16) |
| Who creates the link router | `EditorAreaSplitPanel`, on mount, with the prompt and `closePanel`; every other caller only reads it (RA2-5) | a first-call-wins singleton: an early caller without a prompt disables every move for good |
| Who may frame a preview page | nobody outside the preview partition; `frame-src` own token only | a per-request `frame-ancestors`: the handler cannot see the request type (S1) |
| Request type | `webRequest` `resourceType` in a bounded ledger (S1, S5) | `sec-fetch-dest`: always empty for the custom scheme (S1) |
| Frame refusals | guard on `will-frame-navigate` (depth, count), request filter (remote, foreign token), failed-load writer on `did-fail-provisional-load` -30 (S10) | guard only: never sees frames the browser's CSP refuses (S10) |
| `srcdoc` frames over a cap | shown and listed once per page (answer 9) | blanking by main-run script: best effort, and script in page frames (option 2, not chosen) |
| `_top` / `_blank` inside a frame | no guard; documented as doing nothing | a guard: the sandbox blocks both and main sees no event (S13) |
| Hosts blocked inside frames | parse `console-message` of real subframes in main (S9), capped per second; `frame-src` / `child-src` violations dropped right after the parse | `nodeIntegrationInSubFrames`: a new IPC surface in every frame |
| Frame caps | depth 3, 50 frames; refuse when `framesInSubtree.length - 1 > cap` (S12) | the issue left the count open; 50 bounds the work per load |
| Splitter drag | renderer `drag` occluder; moves held until main confirms the hide; the drag ends on the first end signal (S14) | hide on `pointerdown`: blinks on every click |
| Window-edge drag | `will-resize` / `resized` heard in the app entry, which calls `setResizeHold(windowId, held)`; the service keeps a per-window map; one `release()` gated on the latest wanted state | listeners attached by the service: pulls window events into it (RA5) |
| Unsaved editor | Save / Don't save / Cancel through a save-by-id registry | auto-save or silent discard: loses or writes edits unasked |
| Browser channel | own `browser:` domain | `shell:openExternal`: its allow-list is web-only by design |
| Launch | `open -a <app> <file>` / `<exe> <file>` via `execFile`, no shell | `shell.openExternal('file://…')`: opens the `.html` association, often an editor (P4-AC3) |
| Launch failure | error toast, no fallback | fallback: may open an editor although the user asked for a browser |
| Keys | one table in `src/shared/previewNavKeys.ts`, used by main forwarding and the panel root; physical key (`input.code`) only | two copies (RA12); `input.key`: depends on the keyboard layout (S8) |
| New constants | `src/shared/preview-limits.ts` | `constants.ts`: already 651 lines (moving the whole `PREVIEW` block is recorded debt) |
| New navigation schemas | `preview-navigation-schema.ts`; `PreviewBridge` moves to `preview-bridge-types.ts` | `preview-schema.ts`: already 461 lines |
| Link mode | per tab, renderer only, memory only, default new-tab | persisted: there is no tab restore to attach it to |
| Other windows | today's cross-window refusal banner, unchanged | a variant-id retry for an app that ships one window (RA11) |

## 8. Security notes for Phase 7

- **CSP.** No `frame-ancestors` on any preview response (S2: no value admits an opaque parent without admitting all). Safe because `erfana-preview:` is handled per partition via `session.protocol.handle`, never globally, and Erfana writes the only `frame-src` (own token). Tripwires: `frame-src` is exactly `erfana-preview://<32 hex>`; a malformed token degrades to `'none'` and never throws; `previewSchemeScope.test` fails if the scheme is handled on the default session or the global `protocol`.
- **Frames.** Remote and foreign-token subframes are refused by the browser's own-token `frame-src` before any event (S10), and cancelled by the request filter whatever the allowlist says if they reach it; the failed-load writer lists them. The guard bounds depth (3) and count (50) for `src` frames. `_top` and `_blank` inside a frame are blocked by the sandbox with no main event (S13), so no code handles them. `srcdoc` frames cannot be cancelled (S11); they inherit the sandbox and the CSP (S3), and past a cap they are shown and listed once (answer 9). Frames get no preload; main runs no script in a page frame. The guard fails closed (WI-14): a frame it cannot judge – gone, or a read that throws – is cancelled, and its warning names no URL; past the count cap every new frame is refused with no reads; an unusable own token makes every preview frame a `frame-escape`. Frame documents read for live reload (WI-15) are read only when `confinePath` passes on the path as written and again after `realpath`, and at the real path that passed – HTML only, depth 3, at most 50 documents, through the bounded reader (4 MiB); with no project root none is read, and a refused frame's path is dropped by the watcher's own gate. A FIFO named `x.html` stalls such a read, as it already stalls the entry page's and the handler's (pre-existing).
- **Page scope (RA2-1, RX2-1, RX2-2, RX2-3, RA3-1).** Only the main-document refusal writes into a pending scope; frame, filter, failed-load and console writers keep the committed one, looked up at each write, so a page being replaced cannot write into its successor's badge. The holder's `dispose()` ends a view with both scopes and their timers and emits nothing, so a closed view's late snapshot cannot reach a reopened one. Each scope holds its own CSP-violation bridge and blocked-host sink, so a page spends its own report budgets; a pending scope emits nothing before its commit, and a disposed one ignores late writes (WI-29). The refusal set cuts each address to 2048 characters with no line breaks (CR, LF, U+2028, U+2029) before deduplication and holds at most 100 entries per page; overflow is counted. A frame's `did-fail-load` no longer runs the load-settled path, so page-driven frame failures cannot step the backdrop or trigger the isolated-world colour read. View-level badges (the allowlist's, #115) are kept by the holder and copied into every new scope (the WI-29 follow-up).
- **Console parser.** Page-influenced text: a per-view arrival cap (100 per second) before cutting to 4096 characters and matching, with `Framing` lines and main-frame lines dropped before the cap; level `error`, real subframes of this view within 4 steps; anchored patterns without nested quantifiers, the quoted URL at most 2048 characters and the directive `[a-z-]{1,64}` (S9, S10, S17). The output enters the committed page scope's bridge (`handleCspViolation`), looked up per write, with its budgets and caps. `frame-src` / `child-src` violations are dropped right after the zod parse, before any origin cap or report budget, from either path (RX2-7). Frames still get no preload: `nodeIntegrationInSubFrames` is false (`previewSessionPolicy.ts:43`). **To confirm (WI-14):** a foreign-token frame's entry lists its full URL – the other view's token included – in this view's badge; the page already knew it, and WI-12's filter lists it the same way.
- **Request-kind ledger.** Bounded (256 entries, 10 s), and so is each key: the fragment is dropped and a URL past 2048 characters keeps its head plus its length, so a page-controlled URL cannot grow the ledger (WI-12); the filter notes only what it lets through; an unknown kind only drops a badge and never changes confinement. The filter context is rebuilt in every `PreviewSessionFactory.create` with that session's token, so a recycled partition fails closed – as does an empty own token, a URL that does not parse, or a token in another case.
- **`preview:navigate`.** Invoke; `isTrustedSender`; strict zod; a `Pick<>` slice of the service; the view must be in the sender's window; `open` targets and history targets alike are re-confined on the real root, `.html`/`.htm`, eligible; `back`/`forward` carry the history generation; one pending navigation per panel (a reload is superseded, never pending); a pending intent ends only with its load: commit, replacement or a stop without a commit (S15, S16); `pageChanged.filePath` always comes from a gated history entry, never from the committed URL; resume runs the same gate on `history[index]` (RX2-6); a refusal falls back to the tab's own page, which is located on the real root and then must be `.html`/`.htm` and eligible – else nothing opens, failing closed (QG-7 item 11; part 3 §3.4); an in-page step pushes history only after a real gesture (part 3 §3.5); a first open is located but checks no eligibility (technical debt); the renderer never supplies a URL or token. **To check (G6, G7):** `pageChanged` fires once per `pushState` step, not coalesced – only Chromium's own throttle bounds it; `nativeHistoryOf` (`previewPageNavigator.ts:158`) reads `navigationHistory` through a structural cast and falls back to `loadURL` if the API changes; Back and Forward step with `goToIndex`, so they do not honour Chromium's history-manipulation intervention inside the preview – acceptable if the history stays local to one sandboxed view; the symlink fix's new warning ("Preview open: locating the page failed; loading it as sent") carries the digested panel id and the error name only (`previewViewNavigation.ts:322-325`). `preview:focusPage` (QG-8 U1) is sender-gated before the parse, takes the panel schema only and focuses only a live, drawn view in the sender's window. There is no `preview:setLinkMode` channel.
- **Renderer invariants (RX11, RA2-5, RX2-5).** Navigation provenance never gives `same-tab`; external routing needs provenance `gesture`; only `EditorAreaSplitPanel` creates the router, with the prompt, and a coordinator without a prompt refuses any move that needs one; a prompt that rejects, is dismissed or unmounts counts as Cancel and releases the move lock. No page-controlled value reaches key forwarding beyond the fixed table, or the coordinator, the prompt or the save registry.
- **Resize hold (RX2-4, RA3-2).** The one sanctioned bypass of the overlay guard ends through one `release()` gated on the latest wanted state and called only by the state machine, so a dialog opened mid-hold is never covered by the page; an idle maximum bounds it; the window's entry is dropped when the window closes.

The preview page cannot call it. The e2e seam checks `app.isPackaged` first, receives only `{ via, appPath, filePath }`, and gets its own section in `docs/security.md`.
