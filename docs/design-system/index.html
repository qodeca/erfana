Erfana design system

25 cards, generated from the folder itself. Every page reads a synced copy of the app's design-tokens.css and the real bundled Cascadia Mono, and every number a card quotes is baked in from the source by npm run design – no page runs JavaScript.

  • decided 5
  • proposed 20
  • superseded 0
How to read this. Check a card's status before citing it.
  • decided – binding – the app must match it, or say why at the site.
  • proposed – a direction of travel, not settled law.
  • superseded – kept for history – follow "Replaced by".
A deviation is allowed only when the code says so at the site – /* deviates: docs/design-system/<card> – why */ – and the card lists it under Exceptions. Every marker in src/ is listed in the deviation register. The folder is static by rule: HTML, CSS and images only, guarded by npm run design -- --check and a content security policy on every page. The full rules are in README.md.
Looking for a screen, not a rule? Feature screens built from these cards live in the designs index. A screen cites a card; it never decides a system rule.
