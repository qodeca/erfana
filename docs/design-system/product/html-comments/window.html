Comment window

Where a reviewer types. It is Erfana's own window, drawn over a still image of the page – the page cannot see it, style it, or type into it (decision 4). Every state below is the real CSS.

The shape. A dialog through the dialog stack: role="dialog", aria-modal="true" and a real focus trap. 360px wide (at least 320, at most 480 or the page area less 16px), at most 560px tall; the title and the action row stay put, the body scrolls. Placed right of the element, else left, else below, else above; under 400px of page width it becomes a sheet across the page area's foot. --color-bg-elevated, a 1px --color-border-subtle edge, --shadow-dialog, square corners.

Built from what exists: the buttons are the Buttons card's Dialog.css variants, the banners the Feedback card's one banner, the field and its error the decided Form controls card, the per-message menu the decided Menu card. Proposed, as the plan files it (§10.11); the focus rules in the table below are contracts and are the first candidates for promotion.
Small text is tertiary, never secondary. The context line, the meta lines, the hint and the counter are all --text-sm. --color-text-tertiary on the window measures :1; --color-text-secondary, which much of the app uses for hints, is :1 here – under the 4.5:1 small text needs. The field's edge is --color-border-input, :1, and the focus ring :1, both clear of 3:1.

Live – a real dialog

Try it with the keyboard. Press Open the window: focus lands in the text field. Tab cycles inside the window only. Ctrl+Enter (Cmd+Enter on macOS) saves the focused field; Save on an empty field says why instead of doing nothing; past 4,000 characters the field is marked invalid. Esc closes and keeps your text – open it again and it says “Draft restored”. After Save, focus goes back to the opener and the live region says so.

Saving, and when saving cannot happen

Every error keeps the text. A save is a re-read of the file, a splice and a verified atomic write, so it can fail for reasons the reviewer did not cause. The field stays as it was, a banner above the actions says what happened and what to do, and the assertive live region reads it once. A field problem (empty, too long) sits directly under the field instead, as the Form card requires.

Every save error

The strings are the plan's §10.10 where it gives one, with the file name filled in. Where §10.10 has none, the card uses the fallback in src/shared/errors.ts and says so – those rows are the ones to check.

A thread

Threads in file order; replies one level deep; a resolved thread folds to one line. The author's name is shown; the email sits in a tooltip and the message's accessible description, and is shown in full only when two authors share a name. Times are absolute and local and never count up (“Today, 14:32”). Anyone may edit or delete any message (decision 31), so every message has the same … menu: Edit, Delete…. The UI never implies an author is verified – there is no badge, no avatar, nothing that reads as identity (threat S19).

Plain text, and what it refuses to hide

The body is plain text: white-space: pre-wrap, overflow-wrap: anywhere, dir="auto" on every message, so a right-to-left comment runs right-to-left inside a left-to-right window. A bidi or zero-width control character is drawn as a visible token, so it cannot silently reorder the text around it (threat S18, R-017). Escapes Erfana adds to keep --> out of the file are never shown.
