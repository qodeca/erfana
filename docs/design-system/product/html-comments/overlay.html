Comment overlay in the page

Everything on this card is drawn inside the previewed page, in a closed shadow root, by the preview preload. It is the only part of the comments feature Erfana cannot style with its own stylesheet – so this card shows where every colour comes from.

What is fixed by the plan, and what is still a value. The rules come from locked decisions and §10.2 / §10.5 of docs/designs/html-preview-comments.md: the pin is a speech bubble at the element's top-right (decision 33); several threads on one element are one numbered pin; resolved threads hide their pin; pins are always visible, also outside comment mode, and can be hidden per tab (decision 20). Those are not re-opened here. The card is proposed because the sizes and fills below are still values being chosen, and the plan (§10.11) files the whole HTML-comments set as proposed.

The source. src/preload/previewPageComments/overlayStyles.ts (the rules) and src/main/services/preview/comments/commentOverlayTheme.ts (the values). This card renders a mirror, overlay.css, with each value written back as its token.

The mapping: tokens resolved for the page

The page cannot see design-tokens.css, and must not: a var() in the page would read the page's custom properties, which the page controls. So main sends each value resolved, in commentState.theme, and commentOverlayTheme.test.ts pins each field to its token (R-012). The third column is read from this page's token file as it loads – nothing is typed.

Contrast, derived. The pin's fill against its ink stroke and content, the label's tag on its ink ground and the mode tab's text are all one pair: :1. Hover keeps the ink: :1. A damaged pin's ink ! on the warning fill: :1. The label's text: :1, and its size in the muted grey: :1. All clear the 4.5:1 small text needs.

Why the ring is two-tone. The accent alone on a white page is :1 – under the 3:1 a focus or selection indicator needs (SC 1.4.11). The 1px ink line on both sides of it is :1 there; on a black page the accent carries it instead. Whatever the page paints, one of the two edges clears 3:1. The pin's focus ring uses the same trick: an accent ring with an ink halo between it and the bubble.

Outline and label

Border box only, drawn instantly with no tween: a 2px accent ring with a 1px ink line on both sides. Selected – the element a menu or window is open for – adds a 12% accent fill. The label tag#id.class1.class2… 120×40 sits above the element's top-left, flips below it at the page top, and is clamped sideways. Tag in accent, the rest in paper, the size in grey, always dir="ltr" so a right-to-left page cannot reorder a selector. Two classes at most, then …, 40 characters at most, then a suffix.

The pin

A self-drawn square-cornered bubble, M2 2H22V17H7L2 22Z in a 24 × 24 hit box (WCAG 2.5.8). The tail tip sits on the element's top-right corner, 4px outward, so the bubble floats above the element rather than covering it. Only open threads are counted. One open thread shows two ink "text lines"; 2–9 the number in bold mono; ten or more 9+. A state is never colour alone: hover changes the fill and the cursor and adds a tooltip, selected inverts the whole bubble, damaged swaps the content for !. Pins are never animated.

Not drawn – and this is a state too: every thread resolved, the element not visible now (a hidden slide or tab), the element not found in the file, or pins hidden for this tab. Each of those threads is still reachable from the drawer, which is the guaranteed route to every comment.
A defect this card found on its first render. The number and the ! sit low: they touch the bubble's bottom edge. pins.ts centres the text at y="13" with dominant-baseline: middle, but the bubble's body runs from 2 to 17 in the view box, so its middle is 9.5. The pins above are drawn the way the code draws them, on purpose. The fix belongs in pins.ts (centre near y="10") and then here – open for P6.

Comment mode

Three signals, never one: the toolbar toggle is pressed, a 2px accent frame runs inside the page edge, and a tab at the top centre says “Comment mode – Esc to leave”. The tab moves to the bottom while the pointer is within 48px of the top, so it never sits on what you are trying to pick. The cursor is the system crosshair. The band's height never changes.

Try it: move the pointer over the page below. Elements outline as you pass; near the top edge the tab jumps down. Frames that cannot be commented inside – a refused or srcdoc frame – get a transparent shield, so a click selects the <iframe> element itself (§19 R3-3).

A reveal from the drawer

“Show on page” in the drawer scrolls the element to the centre and draws a static highlight for 1.5 s – the ring plus a 24% fill. Exceptions

Where the overlay departs from the system, with the reason. Each needs a deviates: marker at the site in overlayStyles.ts.

WhereThe systemThe overlay, and why
Every colour and size Tokens only, as var(). Literals interpolated from commentState.theme. A var() inside the page would resolve against the page's own custom properties, which a hostile page sets. The literals come from the tokens through one table, pinned by a test (R-012).
Values written outside the theme Every value from the theme. overlayStyles.ts also writes a 1px ink line, 4px label padding, 2px 8px tab padding, the 12% / 24% fills and line-height: 1.4 straight into the string. The first three equal --border-width, --space-2 and --space-1 --space-4; the line height has no equal token (--leading-snug is 1.375). The R-012 test covers the ten theme fields only, so these can drift from the tokens unseen – open question for P6: add them to the theme, or pin them in the same test.
Pin focus Focus card: the violet ring, and every control in the Tab order. The ring uses the passed-in accent with an ink halo, and pins are focusable but tabindex="-1": a page can carry hundreds, and the keyboard route to every thread is the drawer (§10.8). Recorded in the Focus card's Exceptions.
Forced colours System colours where the theme is replaced. Matches: outline, frame and flash take Highlight; label, tab and pin take Highlight / HighlightText. Listed so nobody “fixes” the literals in that block.
