Comments v2 – toolbars, menus, keyboard and bands

The quieter comment tools in both toolbars, every right-click menu with parallel wording, the Markdown keyboard route and its tab, the non-modal window in the right margin, and the bands that pause or review comments.

Static, proposed. No script: each state is drawn on its own. Plan: docs/designs/comments-v2.md – changes C-08, C-09, C-15, C-16, C-18, C-19, C-20, C-21, C-25 and owner decisions OD-01, OD-03, OD-04. Where a string is not in the plan it is marked derived.

Toolbar – HTML Preview band

C-20. Two comment tools follow Find: Comment mode and a labelled count. Show comment icons has left the row at every tier – it is the drawer's checkbox "Show comment icons and underlines". Only Comment mode uses the pressed signature (fill plus 2px lime edge), so a lit comment tool always means comment mode is on. The ▲ badge counts damaged comments only (C-15, OD-04).

Toolbar – Markdown

C-20, same rules as the band. Comment tools exist only in Preview only. M11, confirmed by OD-03: Split (both directions) and Editor only carry no comment tools and no count – and no icons or underlines in the preview half.

Menus

C-16. Items are parallel: "Comment on selection" matches "Copy selection", then "Comment on the whole {kind}". Markdown uses kind nouns (C-03), HTML says "element". Without a selection the Markdown menu aims at the nearest block, and Copy selection is hidden. OD-01: the HTML Preview now answers a right-click outside comment mode with one item – only when the page did not cancel its own menu.

Markdown – keyboard picking and the comment-mode tab

C-08. The preview scroller is a tab stop (tabindex=0, "Preview of plan.md"). In comment mode the picked block takes tabindex="-1" and real DOM focus, so the screen reader reads its own role and text; the two-tone outline is its :focus-visible ring. Tab / Shift+Tab move between sibling blocks, Alt+↑ / Alt+↓ to parent and child, Enter comments, Shift+F10 or Menu opens the menu at the block, Esc leaves and focus returns to the Comment mode toggle. C-21: Markdown has no floating label – the tab names the target, updated on hover or a keyboard move.

Markdown – the non-modal window

C-18. Same visual window, no backdrop and no focus trap: the preview keeps scrolling and the window follows its block. With at least 376px free right of the 860px column it sits in that margin, top-aligned with the block (else right → left → below → above). Esc closes; an outside click does not; F6 moves focus between window and preview. When the block scrolls away the window collapses to a 28px edge tab.

Bands under the Markdown toolbar

C-09, comments paused. While the editor buffer differs from disk, the preview's icons come from the buffer, but writing is paused: the band says why and offers the way on, Comment mode is aria-disabled (keeps focus, the tooltip says why). The count stays usable, because existing threads stay readable; inside them Reply, Resolve and New are disabled with the band's sentence. Band: the Feedback card's info band – --color-bg-elevated, 1px --color-border-subtle bottom edge, --text-sm; actions are the compact 24px .erf-comment-action (C-26).

Drawer-open look of the countcomments-v2.css and nav.css give an aria-expanded tool the pressed signature (fill plus lime edge).C-20 reserves that signature for Comment mode alone. This card overrides it locally: an open drawer shows a box (--color-bg-tertiary fill, 1px --color-border-subtle) – a shape appears, so it is not colour alone, and it never reads as "mode on". The shared rule needs the same change.
