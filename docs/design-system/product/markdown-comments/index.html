Commenting in the Markdown preview

The HTML Preview's comments, on a Markdown file. A reviewer selects a few words – or turns on comment mode and picks a whole block – and leaves a comment. Erfana writes the same erfana:comment v1 block into the .md file, on its own lines, before that block. The preview hides it; a pin and an underline show it. Everything a comment looks like is the HTML feature, reused unchanged. This card shows only where it lands in the Markdown panel.

Proposed, and static. Plan: docs/designs/markdown-preview-comments.md. These cards carry no script, so every state is drawn on its own and nothing here can be clicked through. The window, drawer, buttons and banners come from ../html-comments/comments.css; the pin, outline, label and mode frame from ../html-comments/overlay.css. Only the Markdown panel, its toolbar tools and the phrase underline are new (markdown-comments.css).
  • Every state – toolbar per view mode, outline labels per block kind, pins, underline, menus, window and drawer.
  • Where the block goes in the file – the slot for each kind of block, and the three places Erfana never writes.
  • HTML Preview comments – the decided cards this one reuses: window, drawer, identity, toolbar, overlay.

5 · comment mode

Pick a whole block

Cmd+Option+M (Ctrl+Alt+M) or the toggle. The HTML mode frame and tab, the two-tone outline and a label of kind · source line. Click opens the window; right-click opens a one-item menu; Tab and Alt+↑/↓ move between blocks in source order.

A table row cannot carry a block of its own, so this comment is saved before the table and names the row inside it. The window says "Saved before the table on line 18."

Exceptions

WhereThe systemHere, and why
Overlay parts inside the block The overlay draws outside .markdown-preview-content (plan §7.1, M7). A static card cannot measure, so the pin, outline and label are children of their block with the same geometry. The shipping overlay is a sibling of the content, so export never sees it.
Underline as a span Shipping uses ::highlight(erf-comment) – no DOM node. A static card cannot call CSS.highlights; .erf-mdc-mark draws the same look.
Fixed positions of the menu and window Placed by measurement: right of the block, then left, below, above. Inline style offsets stand in for the measured placement in each frame.
