Erfana design system / Patterns / Site prompts

Site prompts

proposed not yet reviewed

Every request a page makes of the reader – a permission, a sign-in, a page’s own alert, confirm or prompt, a blocked pop-up, several downloads – is a strip row above the page (.erf-site-prompt in site-prompts.css) that starts with the requesting origin, drawn by Erfana from the engine, never from page text. One row per kind, in a fixed order; more of a kind queue behind it as “+N waiting”. A row never takes focus on arrival unless the reader just navigated or the page is halted. Page-supplied words sit in a box under “{host} says”, plain, clamped and never bold.

Why no existing card covers it. The Permission band (decided) settles one kind of request – the HTML preview’s blocked remote hosts – in one bar, and it is the rule this card keeps: Erfana chrome is a flow sibling above the page, never an overlay. The Feedback band form is one row, at most two actions, no fields. Neither covers a sign-in form, a page prompt(), queueing, the order across kinds, or text a page wrote. Its first user is the built-in browser (spec 025, 025-FR-019, 020, 022, 058).

Rows

One row per kind, in a fixed order

Top to bottom, whatever order they arrived in. A new row appears in one step and pushes the page down once; nothing animates its height (Motion card).

  1. Field error (Feedback band, owned by the address field)
  2. Page dialog, or the leave-page prompt
  3. Sign-in box
  4. Permission prompt
  5. Downloads prompt
  6. Pop-up blocked
  7. Hung-page notice
  8. Keyring notice

One grammar for a request from a frame

Every row that a frame’s request produces names the asker first, then the page that holds it, both from the engine: “{frame host}, inside {top host}, …”. One phrase, one meaning, in every kind – the permission row, the sign-in box, a page dialog. “A frame from …” and “inside a frame from …” are not used: they read both ways, and in the password prompt the wrong reading helps a phisher.

The registrable domain in an origin line never breaks – not at a hyphen, not anywhere (white-space: nowrap on __domain); subdomain labels are quieter (__sub, --color-text-tertiary) and wrap at their dots. The sign-in wording replaces spec 025’s “inside a frame from” fragment, approved by the owner as SPEC-3 (2026-11-01).

Input guard

Owner decision OD-6 (2026-11-01). For about half a second after a row appears or its content changes – including a queue advance, when the next request takes the same row and the same button positions – its answers ignore presses that began before the change, pointer and keyboard alike. Meanwhile they show the Buttons card’s blocked look (aria-disabled, no animation), so a slow or switch user sees why nothing happened. Between one request and the next of a kind, the row clears for a short beat (about 300 ms). The no-focus rule alone does not stop a timed click; the guard does. Rows also push the page down once, so for the same half second clicks on the page are ignored after a row is inserted or removed under the pointer.

A surface of its own

Strip rows sit on --color-bg-secondary, one step off the --color-bg-primary of Erfana’s navigation and pick rows, so the site’s voice is told apart from Erfana’s own chrome without reading (1.34:1 as a surface step; every text pair is measured on the new surface below).

Focus on arrival

RowTakes focus when it arrivesWhy
Permission, pop-up blocked, downloads, hung page, keyringNever; announced politelyA page can time a request under the reader’s Enter or click
Sign-in boxOnly after a navigation the reader started from the toolbarOtherwise a page could steal typing into a password field
Page dialogOnly when its tab is the active tab and keyboard focus is already in that page; otherwise it waits in the strip, is announced, and marks the editor tabIt halts the page’s script – but a background tab can call prompt() while the reader types in a terminal, and focus must never cross panels to catch those keys
Leave-page promptYes, on Stay – the safe answerEnter must not discard the reader’s work

Where focus goes when a row goes. A row that leaves while one of its controls has focus – answered, withdrawn by the page, or a hung page that recovers – hands focus to the next strip row as a whole – the row group, tabindex="-1", inset ring, its name announced – or to one of its non-granting controls (Block, Dismiss), never to a grant. Focus that arrives by restoration re-arms that row’s input guard, so an Enter meant for the row that left grants nothing. With no row left, focus goes to the page, or to the heading of an Erfana page that replaced it. Never to the document.
