Empty, loading and error states

proposed not yet reviewed

A region that has nothing to show says what is missing and what to do next, in one title, one hint and at most one action. A region that is waiting shows inline progress in its own place; only a change that would corrupt state if the user kept working blocks the whole window. A region that failed says what stopped, that the rest still works, and how to try again – and never looks like an empty state.

Why a pattern, not a component. The app already ships all three states, many times over, and each copy centres a grey line of text its own way: different paddings, different gaps, different greys – and one of them fails contrast on the surface it sits on. The consolidation set below lists every copy this card would replace. states.css is the proposed shared shape; adopting it is a consolidation, not one more variant.

Every state

Each frame is a picture of one state on the surface it really lands on. Nothing in a frame takes focus; the keyboard contract is the table below.

Empty

The copy rule. The title names what is missing, in sentence case, without “Oops”, “Sorry” or an exclamation mark. The hint is one sentence that says what to do or why the region is empty – never a restated title. The action, when there is one, is a verb that changes the state (“New file”, “Show all files”, “Clear search”); an empty state with nothing useful to do has no button. Colour: title in --color-text-primary, hint in --color-text-tertiary, icon in --color-text-tertiary. The hint is never --color-text-secondary on the secondary and tertiary surfaces, where it fails: it measures 4.15:1 · fail on the project tree and 3.72:1 · fail on a panel, and both host an empty state. On --color-bg-primary it passes (5.00:1 · pass), which is why the crash screen's details may use it. states.css still uses tertiary for every hint, so one class reads on every surface.

A skeleton screen (grey placeholder rows) is not part of the system: nothing in the app draws one, and this card does not add one.

Loading over time: delay, words, escalation

A wait has a life: most end before anyone notices, some run long, and a few never end on their own. Inline progress follows that life in four steps, and each step is a frame below. The two thresholds are proposed placeholders this card is deciding, not values measured from the app – no component implements either yet.

StepWhenWhat showsWhat a screen reader hears
QuietFrom the start until the show delay (proposed: 400 ms)Nothing. The region keeps what it had, or stays blank. A load that ends here never flashes a spinner.Nothing.
WaitingFrom the show delayInline progress. Where Erfana cannot estimate the wait, words only, no spinner: the sentence names what is being waited for.Nothing new. The sentence is in the status region, but the budget below holds its announcement back.
EscalatedFrom the escalation point (proposed: 10 s)The same sentence, a second one that says it is taking longer than usual, and one Stop action.Once, politely: the two sentences.
EndedThe wait finishes, fails or is stoppedThe content, or the region's error state, or a stopped state with Try again.Once, politely: what happened.
The announcement budget. A wait is announced at most twice: once when it escalates, and once when it ends. Both go through the region's existing polite status (role="status"), never alert and never a second live region. The waiting sentence is not announced on arrival, because most waits end before it would finish being read; a wait that ends during the quiet step is announced only by its result. Stop is never focused automatically – a key press meant for something else must not stop a wait.

A card cannot run the fallback's toggle, but <details> shows the same contract: a control whose state is exposed (expanded or collapsed), and a region that is absent from the accessibility tree while closed. The app keeps its button + aria-expanded + hidden region, because its label changes between Show and Hide – a summary's text does not.

The show delay and the escalation point have no token: they are proposed placeholders on this card. A token for each lands with the first component that implements them.

Open defects this card names

  • Two classes named .erf-progress. This card's states.css uses it for the spinner and sentence; the Feedback card uses it, inside its own page, for a progress bar. A shared feedback stylesheet must rename one of them before both can load on one screen.
  • No wait has a show delay or a Stop. Every loading state in the app appears at once and runs until it ends; the window picker's sentence is announced on arrival.
  • Empty states fail contrast on their surface. .project-tree-empty uses secondary text on the tertiary surface (see the consolidation set).
