Drawer

proposed not yet reviewed

A drawer is a flow sibling at the inline end of a view, never an overlay: the content beside it shrinks, and nothing is covered. It opens in one step, sits between a minimum and a maximum width, and below a 640px host it takes the whole width. Inside, top to bottom: a header (title and a close button), a fixed controls band, a note slot that stays in view, and one list that scrolls. Opening puts focus on the close button; closing returns it to the button that opened the drawer.

Why not a dialog or a popover. A drawer is for work done beside the content – a list of comments next to the page they point at. A dialog would block the page and a popover would cover it. A Dialog stays the answer when the reader must decide before going on. The close button is the Buttons card's .erf-button--icon; the filters are a Segmented control; the list is the Rows and lists card's.

PartClassRule
Host.erf-drawer-host, .erf-drawer-host__contentA flex row. The content shrinks; it is a size container, so the full-width switch needs no script in plain DOM.
Drawer.erf-drawer<aside aria-labelledby> – a named complementary region. Width --erf-drawer-width (default --comments-drawer-width), at least 280px (the shipped floor), at most 480px. A start border, no shadow, no z-index.
Header.erf-drawer__head, .erf-drawer__titleThe title is an h2 in the panel-title weight; a long title truncates. The close button follows it.
Controls.erf-drawer__controlsFilters and options that act on the list. Never scrolls; a rule closes it off.
Note.erf-drawer__noteOne message about the whole list, in a banner. Above the scroller, so it stays in view.
Scroller.erf-drawer__scrollThe only part that scrolls. It holds the list, or the list's empty, loading or error state (the States card).

The keyboard contract

The drawer is not modal: Tab moves in and out of it freely, and the page beside it stays reachable. Inside, each part is one tab stop – the close button, the filter group, each option, then the list.

Open defects this card names

  • No ceiling. The comment drawer has a floor but no maximum width.
  • A typed floor. min-inline-size is a literal (280px) (marked as a deviation from the comments design).
  • Focus return is untested. Closing hands focus back to the opener in usePreviewComments.ts, and no test holds it.
  • A one-off close button. .erf-comment-icon-btn re-implements the icon button.

Related

Exceptions

None recorded. A shipping drawer that departs from this card carries a deviates: marker at the site and gets a row here, naming the file.
