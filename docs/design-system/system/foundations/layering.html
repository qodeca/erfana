The rung that breaks the ladder

The white rung at the top is not styled by CSS and cannot be out-ranked. The HTML preview runs the page in a native view that the operating system composites above all sibling DOM. A button given z-index: 999999 still sits underneath it.

So the ladder describes the DOM's internal order only. Above it sits a layer with no number. The app's answer is procedural, not declarative: one service owns whether that view is visible, and a lint rule stops anything else touching it. Anything that must appear over a preview either lives outside the preview's rectangle, or hides the view first.
Proposed – HTML preview comments use both answers. The comment menu and the comment window hide the view first: the page is swapped for a still image while they are open, and they take the context-menu and dialog rungs above. The drawer lives outside the rectangle, as a flow sibling that shrinks the page. Inside the page, the outline and pins sit in the page's own top layer (the Popover API), a rung of the page's ladder rather than Erfana's; a page dialog opened later sits above them (plan §19 R3-7). See the proposed Commenting on a page screen.

Two things to fix

The blocker does not block. --z-blocker is annotated "above everything" and sits below every dialog and every context menu. It is the layer shown while a project switches – precisely when a dialog might be open. Either renumber it above --z-context-menu, or rename it to what it actually is.
Bare z-index values on the app-wide ladder. Stylesheets that set one instead of a token: 1. Among them is the active-tab underline in AppDockLayout.css, which writes the exact value of --z-dropdown (100), so when the underline and a dropdown overlap the winner is decided by DOM order, not intent. Give it its own rung or a local stacking context; never a number.

That count is CSS only. More bare values live in TypeScript, where no stylesheet lint will ever see them – see the rule below.

Dialogs

6 renderer components declare aria-modal. Each takes its z-index from DialogContext, counting up from --z-dialog, and the shared BaseDialog traps focus while it is modal (#91, closed). The modal shell has no card of its own yet.

The rule

Never write a raw z-index. If no rung fits, add one to the scale – do not squeeze a number in between. And never mirror a token into TypeScript: 8 renderer files currently carry a z-index literal in TS – BASE_ZINDEX in DialogContext and OVERLAY_BASE_ZINDEX in useOverlayOccluderStore mirror --z-dialog and --z-modal outright, and the rest pass literals in as JSX props. Changing the CSS silently desynchronises the runtime.

This sentence used to say "two files", counted by hand, and was wrong – it saw the two constants and none of the prop sites. It is now derived, which is the only reason it can stay right.

Exceptions

None recorded. A shipping component that departs from this card carries a deviates: marker at the site and gets a row here, naming the file.
