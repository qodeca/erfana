Erfana design system / Foundations / Writing

Writing

proposed not yet reviewed

Every string in Erfana is written in sentence case, uses an en dash where a dash is needed, puts a verb on every button, says in an error what happened and what to do, writes shortcuts the way the platform does, and never claims that Erfana itself is an AI.

Case

Sentence case everywhere – titles, buttons, menu items, tabs, settings, tooltips, toasts. Capitalise the first word and proper nouns only: Erfana, Claude Code, Markdown, Mermaid, GitHub, macOS, Windows. Uppercase is a style two roles apply with CSS (panel titles and column headers – see Typography), never typed into the string, so a screen reader does not spell it out and a translation is not shouted.

Buttons say what happens

A button is a verb, or a verb and its object: the reader should know what will happen without reading the dialog. The confirming button repeats the title's verb. Cancel is always "Cancel". "OK", "Yes" and "No" are never a choice – they make the reader go back and re-read the question.

Errors say what to do

Three parts, in this order: what happened (in the reader's words, naming the thing), why if it is known, and what to do next. No blame ("you entered an invalid…"), no apology theatre ("Oops!"), no bare codes – a code goes after the sentence, for a bug report. The toast keeps the full file name; the log file gets it redacted (redactUserInput).

A field error sits under its field, is linked with aria-describedby and aria-invalid, and says how to fix the value: "Enter a port between 1024 and 65535", not "Invalid input". See Form controls.

Erfana hosts the agent – it is not one

Erfana is a workspace with a terminal that runs a CLI coding agent of the user's choosing. The intelligence is the agent's. Copy that blurs this overclaims, and breaks the day the user runs a different agent.

WriteNotWhy
"the agent", "your coding agent""Erfana's AI", "the assistant"Erfana has no model of its own
"Claude Code" – only where the feature really is Claude Code-specific (the context-window meter reads its transcripts)"Claude" for anything the terminal does with any agentNaming one vendor for a generic feature is false for every other agent
"Ask the agent to explain this""Erfana will explain this"The action sends a prompt; the agent answers
"Agent-native Markdown workspace""AI-powered editor"The product's own description, and the true one

Product words

Proposed. One word for each thing the reader handles, used the same way in every preview, menu, tooltip, announcement and error. The words below are the comment feature's, because that is where the vocabulary drifted first: the HTML preview shipped its own nouns, and the Markdown and selection comments inherited them. Decided for the comment feature by Comments v2 (C-03 and the toolbar finding); this card makes them the app's words.

WordMeansWrite it like this
commentOne message the reader wrote, and the stored item in the file. Always "comment" – in both previews, in a delete and in an error“Delete comment”, “Couldn't save the comment.”
threadA first comment and its replies, about one target. Only where the difference from one comment matters – a delete, a count of conversations“Delete thread”, “3 threads”
replyA comment that answers a thread's first comment. The verb is the button“Reply”, “2 replies”
iconThe small mark drawn on the preview beside a commented target. The reader's word for it, in every string“Show comment icons and underlines”, “Its icon comes back when it does.”
underlineThe mark under a commented phrase of text. Written “underline” in UI text; mark is the design and code name for the same thing and stays out of the UI“Show comment icons and underlines”
selectionText the reader selected to comment on. Not “highlight” – the app also highlights search results“Comment on selection”
comment modeThe mode in which a click on the preview chooses a target instead of following a link. Lower case inside a sentence, capital at the start of a label“Comment mode · List item, line 14 · Esc to leave”

The limits a sentence may quote are read from the code, not typed: COMMENT_MAX_CHARS = 4000 characters in one comment or reply, with the counter warning from COMMENT_WARN_CHARS = 3600; 200 replies in a thread; 500 threads in one file before its comments turn read-only; files of up to 25 MB. A string that states one of them builds it from the constant, as FILE_LIMIT_TEXT does (commentCopy.ts:40–42).

Casing. A noun is capitalised at the start of a label, a title or a row and lower case inside a sentence: “List item · line 14” in the drawer, “Showing list item, line 14.” as an announcement, “Comments on H2 heading “Next steps”” as a window title. “H2” keeps its capital everywhere, because it is a name. “Code block” and “HTML block” are the only places the word block may appear – as part of a Markdown noun the reader already knows.

These strings are right for the HTML preview and must not reach a Markdown or selection comment: “elements” in the file limit (commentCopy.ts:42), “page too large – it has too many elements” (:71), “Show on page” (:234) and “This element isn't on screen right now” (:259).

Numbers and names

  • Numerals for every count and size ("3 files", not "three files") – they scan faster in a dense UI.
  • Units with a space, except % and px: "2 KB", "1.5 s", "50%", "24px".
  • Paths, file names, hosts and commands go in the mono face and are never truncated in the middle of the part that identifies them – see Rows and lists.
  • Name a thing the same way everywhere: if the panel is "Project", the menu does not say "Explorer".

Exceptions

None recorded. A shipping string that departs from this card carries a deviates: marker at the site and gets a row here, naming the file.

Open defects this card names

  • Two macOS shortcut notations. commentCopy.ts types "Cmd+Option+M" and "Cmd+Enter" for macOS, while formatShortcut renders the glyph form (⌥⌘M) everywhere else.
  • Em dashes in the permission band. Shipped strings use an em dash where this card asks for an en dash (shown here as ⟨em dash⟩, because no page in this folder may carry the character): the confirm sentence “but Erfana cannot limit it to that ⟨em dash⟩ the host will also be able to run code…” (PreviewBandConfirm.tsx:169–170); the four approval failures “Not saved ⟨em dash⟩ list full”, “Not saved ⟨em dash⟩ not allowed”, “Saved ⟨em dash⟩ reload to apply” and “Not saved ⟨em dash⟩ check settings” (permissionBand.logic.ts:354–372); and “Only the first hosts are listed ⟨em dash⟩ this page asked for more.” (PreviewChromeBand.tsx:420).
  • Em dash in the clipboard toast. “Could not access the clipboard ⟨em dash⟩ another app may be using it. Try again in a moment.” (textClipboard.ts:44–46). It also says “Could not” where the app's other errors say “Couldn't”.
