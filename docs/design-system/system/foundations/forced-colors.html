Forced colours

proposed not yet reviewed

On Windows, a contrast theme replaces every colour Erfana chooses with a handful of system colours, drops every background image and box-shadow, and flattens fills. The rule: every state that carries information – focus, selected, pressed, checked, disabled, invalid – keeps a border, an outline or text that survives that, and a state repainted for forced colours uses the system colour named below for it. A state that is only a fill or a shadow vanishes.

The rules

  1. Every state keeps an edge. Selected has a border edge, pressed has a border edge, focus is an outline. A fill alone is gone in a contrast theme; an edge is repainted in a system colour and stays.
  2. Focus is an outline, never a box-shadow. Forced colours remove box-shadow; the one ring is an outline, so it survives with no extra rule. A transparent outline or border is a legitimate placeholder: the browser paints it in a system colour.
  3. Use the system colour for the meaning, from the table below – not the one that happens to look right in one theme.
  4. forced-color-adjust: none is a last resort, for a control whose state is drawn only by fill (a custom checkbox, a thumbnail picker), and it must then repaint every state with system colours itself. Settings, the screen and window pickers and the screenshot overlay do exactly this.
  5. Icons are currentColor, so they take the system text colour; an icon painted with a token fill disappears or keeps a colour the user did not choose.

Every state, simulated

The rule, in code

/* A state drawn by fill needs an edge that forced colours keep. */
.erf-toggle[aria-pressed="true"] {
  background: var(--color-bg-selected);
  border-bottom: var(--border-width-thick) solid var(--color-brand-lime);
}
@media (forced-colors: active) {
  .erf-toggle[aria-pressed="true"] { border-bottom-color: Highlight; }
}

/* A control drawn only by fill opts out and repaints every state itself. */
@media (forced-colors: active) {
  .erf-check { forced-color-adjust: none; background: Canvas; border-color: CanvasText; }
  .erf-check:checked { background: Highlight; border-color: Highlight; }
  .erf-check:disabled { border-color: GrayText; }
}

Try it for real

These controls carry the rule live. Turn on a Windows contrast theme, or in Chrome DevTools open Rendering and emulate forced-colors: active, then Tab to them: the pressed toggle keeps a Highlight edge and the ring turns Highlight.

Known gaps

  • The screen and window pickers draw their selected and focused ring as a 3px box-shadow. Their forced-colours block repaints the item with Highlight, so they survive there – but the default ring is still a shadow, and a fourth ring idiom (Focus card).
  • Nothing checks this mechanically. For this card only the stylesheets that already carry a forced-colours block were read; a state elsewhere drawn by fill alone has not been audited.
