Typography

proposed reviewed 2026-08-31

Erfana is a desktop editor, so the type scale is small and dense: chrome text is 13px, not 16px. Text is set by role, not by size – pick a row from Text styles before you reach for a token. Every sample below is rendered at its true size in the bundled face.

Text styles

Proposed. Six roles cover almost every string in the chrome. Each is a fixed bundle of family, size, weight, leading, case and colour; the contrast cell measures the role's colour on a panel (--color-bg-secondary) against the 4.5:1 that text needs.

Hints use tertiary text, never secondary. --color-text-secondary on a panel measures 3.72:1 · fail – it is a label colour for the darkest surface only. A hint is text someone has to read, so it takes the colour that passes everywhere.

Uppercase is for two roles only – panel titles and column headers – and always with tracking. Never uppercase a sentence, a button label or anything longer than three words.

10px and 11px are label sizes, not reading sizes. Use them for a chip, a count, a panel title or a one-line hint. Anything a reader has to read as a sentence or more starts at --text-base.

Document size

--text-prose is not an eighth step of the scale. It is the body size of rendered document content – the Markdown preview – which a reader stays in for minutes. Headings inside the preview scale from it in em. Chrome never uses it.

Line heights

Each leading is drawn as the same three-line paragraph over a grid with one hairline at the foot of every line box, so the space a line takes is measured, not described.

Rendered documents

Tracking for uppercase labels

Proposed: one token, --tracking-caps: 0.06em. Capitals set at 10–11px without tracking crowd into a block. The app adds tracking today as pixel literals, typed per stylesheet and not all the same value. In em it scales with the size it sits on, so one value serves both label sizes.

One sans stack, not two

Proposed: retire --font-system and point its one reader at --font-sans. Both stacks start with the same three faces (-apple-system, BlinkMacSystemFont, 'Segoe UI'), so on macOS and Windows they resolve to the same font and the two samples above are identical. They can only differ on Linux, where --font-system skips the distribution faces and falls to Roboto or the generic sans – the opposite of "the system face". A second name for the same intent is how a scale grows a fourth member nobody chose. Today it is read in MermaidToolbar.css, so the migration is a small change, then the token moves to the retired strip on this card.

Zoom, reflow and text spacing

Three WCAG 2.2 criteria decide how text behaves when the reader changes it. None of them is satisfied by the type scale alone; each is a rule about the box the text sits in.

CriterionWhat the reader doesThe rule for Erfana
1.4.4 Resize text (AA)Zooms the window to 200% with View → Zoom in (⌘+ / Ctrl+) Nothing is lost or clipped. Text sizes are pixel tokens and page zoom scales pixels, so the scale itself is fine; what breaks is a fixed height around text. Size a text container with min-height and padding, never height. Never disable zoom.
1.4.10 Reflow (AA)Zooms until the window is the width of 320 CSS pixels Chrome reflows into one column with no sideways scrolling: labels wrap or truncate with the full text available (a tooltip is not enough – the accessible name carries it). Exempt by the criterion: content that needs two dimensions to mean anything – the code editor, the terminal, a wide table, a diagram. They may scroll both ways; the panel around them may not.
1.4.12 Text spacing (AA)Applies a stylesheet setting line height 1.5, paragraph spacing 2em, letter spacing 0.12em and word spacing 0.16em No text is clipped or overlaps. Same cause as 1.4.4: a fixed height with overflow: hidden on a text box. A chip, a tab or a row grows; it does not crop.

Exceptions

None recorded. A shipping component that departs from this card carries a deviates: marker at the site and gets a row here, naming the file.
