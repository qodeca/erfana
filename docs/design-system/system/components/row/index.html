Rows and lists

decided reviewed 2026-10-28

The densest thing in Erfana. A file tree row, a picker option, a host in the permission band – all the same primitive: one selected state, one keyboard contract, and no state carried by colour alone. The frames below walk the keys one press at a time.

The decision. Erfana has four different ways of showing that a row is selected: a lime left border in the tree, an outline in the file picker, and a border-colour swap in two other pickers – where hover and selected are so close they are hard to tell apart. The tree's version wins: a filled background plus a 2px lime edge. It is the most used, it survives losing focus, and the edge marker is Erfana's own signature – the activity bar uses the same idea for the active panel.
Every class here is prefixed erf-. Not cosmetic. Mermaid puts class="row" on gitGraph commit labels and on its generic label path, and Erfana injects that SVG with innerHTML – so a bare global .row would reach into diagram labels in the preview and in exported images. Nothing defines .row in the app today, which is the only reason this has never bitten.

The markup

Roving tabindex: exactly one row is 0. A folder's children sit in a nested role="group" that is a sibling of the folder's row, never inside it – a treeitem that wraps its children makes the folder's name swallow its contents (#89). Every row states its level, position and set size, because the tree is virtualised and assistive tech cannot count rows that are not rendered. The git letter is drawn aria-hidden and spoken from visually hidden text (“, untracked”) – real text is read in order and survives translation, where an aria-label on a span may not be read at all.

One Tab stop, not one per row. A tree of 400 files with a Tab stop each is unusable – that is why the roving pattern exists: the list holds the tab stop and moves focus internally with arrows.

The file tree now follows this contract (#87, #88, #89). It uses a roving tabindex, not the aria-activedescendant an earlier version of this card used: the row that has focus carries tabIndex="0" and every other row -1. The tree is virtualised, so only the rows in view are in the DOM, and roving keeps real DOM focus on a row. That is what dnd-kit, focus recovery after a rename, and the ring all key off. The focused row and the row being dragged are always kept mounted. Each row states aria-level, aria-posinset and aria-setsize, because assistive tech cannot count rows that are not rendered.

Before that, the tree had the inverse. ProjectTreeNode.tsx spread dnd-kit's drag attributes onto every row, and useDraggable defaults to tabIndex: 0 plus role="button", so every row was a Tab stop that no key operated. The fix had to drop those attributes first: they put 0 on every row, and roving needs 0 on exactly one. The tree keeps only dnd-kit's pointer listeners.

Narrow the frame until the hosts stop fitting. Every one must still end in its registrable domain – the part that decides whether you are about to trust evil.com. If any row ends up reading cdn.jsdelivr…, the control is broken. Here none can: they wrap onto a second line instead of losing an end.
This used to be one CSS rule, and it was backwards. direction: rtl put the cut at the front; the next line, unicode-bidi: plaintext, threw that away and took the direction from the first strong character instead. Hostnames start with a Latin letter, so the paragraph came out left-to-right and the ellipsis went back to the tail. The rule delivered the exact trap its own comment described. It survived because no card ever rendered a host long enough to cut.
So nothing is cut at all. The guarantee is not a cleverer truncation, it is the absence of one: a host that does not fit wraps. There is no truncated end, so there is no wrong end to truncate, and the rule needs to know nothing about the host's structure.

A three-element flex front-elide was built first and did work – the prefix shrank and elided, the domain refused to. It is rejected for a different reason: it has to be told where the registrable domain begins, and only the Public Suffix List knows that. Last two labels is wrong for example.co.uk, and a front-elide cutting at the wrong boundary is worse than no invariant at all, because it looks like one. Erfana carries no PSL. If one ever arrives for another reason, revisit – one-line rows read better than wrapped ones.
A row grants an origin, so a row has to show one – without becoming unreadable. The scheme and the port are drawn only when they are not the default: the scheme when it is not https, the port when it is not the scheme's own. So the ordinary row is exactly what it always was, and http://localhost:3000 is legible because it looks different. Both parts are dimmed with --color-text-tertiary (7.06:1 · pass on the tree) – never --color-text-secondary, which measures 4.15:1 on the same --color-bg-tertiary and fails AA for text this size. De-emphasised is not hard to read.

Neither gets a <wbr>. Break hints mark preferred break points, so a part with no hint beside it stays attached to the host unless the line genuinely cannot fit. That is what stops localhost and :3000 landing on two lines and reading as two separate things. Only the port carries white-space: nowrap, so the number itself never splits; the last label and the port are deliberately not wrapped together in a nowrap group, because that group could then overflow the row instead of wrapping – and overflowing is how a host stops being fully visible.
A trailing dot is normalised away, not refused. evil.com. and evil.com are the same name to a resolver, and a CSP host-source has no empty-label production. Refusing it would produce a blocked row that gets an Allow button the boundary then rejects – a button that lies, which is worse than no button. One trailing dot is stripped; example.com.. is not a host and stays refused.
Two things CSS cannot decide. Truncation is not the only way to lie about a host: аpple.com with a Cyrillic а truncates perfectly and is still a different domain. Render the punycode form when the label mixes scripts. And what a screen reader hears must be the full host, in real text: the row draws the host aria-hidden and puts a visually hidden copy beside it (.erf-host__announced, “Host https://evil.com”). Not title – unreachable by keyboard and by touch – and not aria-label on the span – ARIA does not let a generic element be named, so a screen reader may drop it. The <wbr> break hints after each dot stay in the drawn copy only.

Never colour alone. The git badge carries a letter, not just a hue. A cut row gets a dashed underline as well as a dimmer name. A drop target gets a solid edge, a rejected drop a dashed one. Someone who cannot separate the colours still sees every state.
Hover and selected must not look alike. Hover is a flat background change. Selected adds the lime edge. In today's file picker they share one declaration, so a pointer passing over a row looks identical to the row you chose.
Cut dims the name, not the row. The name turns --color-text-tertiary (7.06:1 · pass) and gains the dashed underline. An opacity fade would dim the badge and the focus ring with it – the “cut + focused” frame keeps a full-strength ring. ProjectTree.css still ships the fade, at opacity: 0.6; adoption replaces it.
The drop edge is solid --color-accent-drag. It measures 6.95:1 · pass against the tree and 4.68:1 · pass against the drop fill. The --color-accent-drag-border tint it replaces composites to 1.84:1 · fail – the one shape that says “drops here” was the faintest line on screen (WCAG 1.4.11 asks 3:1 of a state indicator).

Six, not four. This card used to paint backgrounds for four states and seed only three, so a renamed or conflicted badge was a near-black label on a transparent row – measured 1.20:1 · fail against --color-bg-tertiary, which is invisible. Nothing rendered them, so nobody saw it.

The app itself already ships all six. This was a defect in the card, and adopting the old version would have made the app worse – which is the argument against the "copy this in verbatim" note this file used to carry.

Every drag has a route without one

WCAG 2.2 SC 2.5.7 (Dragging movements): anything done by dragging can also be done with single clicks or the keyboard. Moving a file in the tree is a drag, so it needs a second route – and a screen-reader or switch user cannot drag at all.

The drag stays; it stops being the only way. Cut and Paste already move a file with the keyboard or two clicks, which is what SC 2.5.7 asks for. Move to… is the proposal on top: Cut and Paste make a keyboard user walk focus to the target folder, which in a deep tree is most of the work.

Exceptions

Where the shipping component departs from this card, with the reason. An undocumented deviation is a bug; a documented one is a decision.

WhereThe cardThe component, and why
Welcome tab, recent projects Tab enters the list once – not once per row. The list is one Tab stop for opening, plus the active row's Remove button as a second stop. Removing a project then needs no extra shortcut to learn, and every other row's Remove stays out of the Tab order, so the cost does not grow with the list. Arrows, Home and End move between rows as the card says. See WelcomePanel.tsx (PR #286).
HTML-preview comments drawer Tab enters the list once – not once per row. The same shape as the Welcome list, and it ships. The list is one Tab stop: ↑ ↓ Home End move between rows, and Enter or a click is Show on page with focus staying in the list (Open in source on a not-found, damaged or newer comment). Tab once more reaches the active row's Open, which opens the comment window; every other row's Open stays out of the Tab order. The rows scroll, so they draw the inset ring. See CommentDrawer.tsx and CommentDrawer.css, and the Comments drawer card.
