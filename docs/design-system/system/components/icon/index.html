Icons

Erfana draws icons with a single library, imported directly rather than through the shared registry in files. That part is fine. The sizing is not.

The problem, counted. 161 icons are sized with a number typed at the call site — size={14}, size={18}, size={48} — across eight different values. Three of those eight exist nowhere in the token scale. The box around the icon is tokenised in 34 places; the icon inside it never is. A shared registry does exist, defaults to 14 — itself off-scale — and files bypass it. Two do use it, both context menus, which is the shape of the fix rather than an exception to it.

The five sizes

The decision. Icons take a size name, never a number. The three off-scale values map to the nearest token: 14 → sm (16), 18 → md (20), 48 → a new --icon-size-2xl. Nothing else is added — eight sizes for one small app is four too many.

Does this icon have a name?

This is the only accessibility question an icon raises, and it has exactly two answers.

No — it sits next to words. The icon repeats what the label already says, so a screen reader announcing it twice is noise. Mark it aria-hidden="true". This is the common case.

No — but its button does. The icon stays hidden; the button carries aria-label="Close preview". Never put the label on the glyph inside a button — that is one name too deep.

Yes — the icon is the information. A git status dot with no text beside it. Give it role="img" and an aria-label. Erfana already does this correctly on file badges.

The third case is the one that gets missed. A colour or a shape carrying meaning on its own needs a name, or the meaning is invisible to anyone not seeing colour. Erfana's sidebar footer currently fails this: it shows M3 U2 D1 where only the colour separates modified from deleted, with no label at all.

Minimum target

An icon that can be clicked lives in a target of at least 24 × 24 — WCAG 2.2 SC 2.5.8. The glyph itself is usually smaller: a 16px icon centred in a 24px button is the standard pairing, and it is what the button above does. Never shrink the target to fit the glyph.
