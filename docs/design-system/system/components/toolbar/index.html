Toolbar

proposed not yet reviewed

A toolbar is one row: groups of controls, a separator between groups, a spacer that pushes the rest right, and a More button that collects whatever does not fit. It is one tab stop; the arrow keys move between its controls. No control is ever clipped while the keyboard can still reach it.

What this card does not decide. The icon button, the toggle (aria-pressed) and their states are the Buttons card's; the pressed toggle in a band is drawn on the Permission band card. The frames below load the Buttons card's button.css – .erf-button--icon and .erf-button--toggle – so a toolbar built from this card has one button style, not two. This card owns the row: spacing, grouping, overflow and the keyboard.

A role is a promise – the rule the Menu card set. These declare role="toolbar" today and implement none of its keyboard:
  • The Markdown toolbar – MarkdownToolbar.tsx: one Tab stop per control, no roving tabindex, no arrow keys.
  • The Mermaid toolbar – MermaidToolbar.tsx: the same.
  • The image viewer toolbar – ImageViewerToolbar.tsx: the same.
  • The preview band's bar – PreviewChromeBand.tsx:335, role="toolbar" named “Preview”: no ← → between its tools. Its only arrow keys move between the Allow buttons in the blocked-host list, which is not the bar.

Either the keyboard below is added, or the role comes off and the controls stay a plain row of tab stops. A role without its keyboard tells a screen-reader user to press keys that do nothing.

View modes beside toggles

A toolbar often holds both kinds of state: a view-mode group (one of many, always exactly one) and on/off toggles (Wrap, Show pins). They must not look alike, or a reader cannot tell “this is the current mode” from “this is switched on”.

ControlRole and stateLook
View mode, the selected onerole="radio" in a role="radiogroup", aria-checked="true"Filled (--color-bg-selected) and a bright glyph – no lime foot
Toggle, onaria-pressed="true"Fill plus the lime foot
Either, offaria-checked="false" or aria-pressed="false"No fill, a tertiary glyph

Both looks are .erf-button--toggle; the attribute picks the look, so nothing extra is written. The mode group sits in its own erf-toolbar__group, with a separator between it and the toggles.

Tool height

One height for every tool in a toolbar, and for anything that has to line up with one: a count button (“3 comments”), a menu button, a find field, a floating action over a canvas. The proposal is a token, --toolbar-tool-height, at the value of --input-height-sm (28px). It is a proposed token, not yet in design-tokens.css; adding it is an owner decision. Until then toolbar.css carries a card-private fallback, --erf-toolbar-tool-height, that every frame on this card reads, and a comment saying to delete it when the token lands.

TokenValueWhere it is the height
--btn-height-sm24pxThe target floor: an icon button in a tree row, a dialog header, a tab's close. Not a toolbar tool.
--toolbar-tool-height proposed28px, the same as --input-height-smEvery toolbar tool, and what aligns with one. Above the target floor, and on the same line as a small field, so a find field and its tools share both edges.
--btn-height-md32pxA text button in a dialog, a panel or settings. Not a toolbar tool: too tall for a dense row.

An icon-only tool is a square of the tool height. A text tool, a count button or a menu button takes the height and keeps its own width. The Markdown toolbar already draws its tools this tall (the Buttons card records it as an exception); this makes it the rule instead of a literal.

The keyboard contract

The WAI-ARIA toolbar pattern, with a roving tabindex. A text field inside a toolbar keeps its own ← →; Tab leaves it.

Open defects this card names

  • role="toolbar" without its keyboard – MarkdownToolbar.tsx, MermaidToolbar.tsx, ImageViewerToolbar.tsx: no roving tabindex and no arrow keys, so every button is its own tab stop. The preview band's bar (PreviewChromeBand.tsx:335) declares the role with no ← → either.
  • View-mode buttons carry their state in a class only – MarkdownToolbar.tsx marks the current mode with .active and no aria-pressed or aria-checked, and the modes are not a radio group, so a screen reader cannot tell which mode is on.
  • Literal sizes – MarkdownToolbar.css sets its buttons to height: 28px (lines 72 and 102) and its separator to width: 1px, off the button scale and the border token. The height is the proposed tool height; it becomes the token once --toolbar-tool-height exists.
  • The image viewer scrolls instead of overflowing (#73) – a locked requirement there, kept as a legitimate exception once it carries a deviates: marker.
