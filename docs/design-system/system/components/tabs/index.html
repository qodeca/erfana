Tabs

proposed not yet reviewed

One tab, .erf-tab, for every document a panel group shows. The selected tab has a lime underline in every group; the focused group sits on the panel surface. Unsaved and deleted are said in a shape and in words, never in colour alone, and both are part of the tab's name. Close is a 24 × 24 pointer target that is hidden from assistive technology; the keyboard closes a tab with Delete or the tab menu's Close.

Why a card: three copies already drift. EditorTab.css, HtmlPreviewTab.css and ImageTab.css each carry the same tab under its own class name. EditorTab.css and ImageTab.css type height: 41px (2 of the three files) where HtmlPreviewTab.css reads --tab-height (41px); the same two give the close button border-radius: 0 (2 files) where HtmlPreviewTab.css reads the token; the width floor and ceiling are typed in 3 of the three, and again as !important dockview overrides. tabs.css is the one file they become.

Contrast

Every text colour a tab takes, on every surface it sits on. Text needs 4.5:1; the underline, the glyphs and the ring are non-text and need 3:1. A tab in an unfocused group takes --color-text-tertiary, not --color-text-secondary: secondary measures under 4.5:1 on the strip.

The underline and the stacking order

Today the active underline is an ::after with z-index: 100 in AppDockLayout.css – the exact value of --z-dropdown, so where the underline and a dropdown overlap, DOM order decides the winner (the Layering card records it). This card removes the number instead of choosing a rung: a positioned ::after already paints above the tab's own content, and .erf-tablist sets isolation: isolate, so nothing inside the strip takes part in the global stacking order.

The keyboard contract

The strip is role="tablist"; each tab is role="tab" with aria-selected and aria-controls its panel; dockview owns those attributes today. One tab stop for the whole strip (roving tabindex). Activation is automatic – the panels are already mounted, so moving is cheap.

Names, said once. A tab is named with aria-labelledby: its label, then its state span – “unsaved changes” (visually hidden, beside the dot) or the visible “(deleted)”. So a listener hears “README.md unsaved changes, tab, 2 of 4”. The full path is its description (aria-describedby, the tooltip), never title. The close button is not part of the tab for assistive technology: a role="tab" cannot hold another control, so the close is aria-hidden and pointer-only, and Delete and the tab menu's Close are the stated route.

Defects this card names

  • No keyboard in the strip. No arrow-key, Home/End or Delete handling, no roving tabindex, and no test for any of it.
  • A control inside a tab. EditorTab.tsx puts a <button> named “Close <file name>” inside the tab, with title="Close" as well – a nested interactive control that assistive technology may flatten or skip.
  • The path lives in title. The tab's full path is its title, which the keyboard never shows and a screen reader may read as the name.
  • The dirty dot names nothing. It is an empty <span> with aria-label="Unsaved changes" and no role, so many screen readers skip it.
  • The close button hides from the keyboard. It shows only on hover or when dirty – never for keyboard focus and never on the selected tab.
  • A stacking tie. The active underline's z-index: 100 ties with --z-dropdown (AppDockLayout.css).
  • Three copies of one tab, with the drift listed above.

Exceptions

None recorded. A shipping tab that departs from this card carries a deviates: marker at the site and gets a row here, naming the file.
