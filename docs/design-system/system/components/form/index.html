Form controls

decided reviewed 2026-08-31

One text field, one select and one checkbox. The boundary is --color-border-input, hover brightens it, focus draws the one ring, and a field has exactly one name. An error is three things at once – aria-invalid, a red edge with an icon, and a message the field names with aria-describedby – and on submit, focus goes to the first field that failed.

These controls were invisible, and it was a token defect, not a card defect. --color-bg-input and --color-bg-secondary resolve to the same colour, so a field's interior is pixel-identical to the panel behind it. The only thing marking the control is its border – and that border was --color-border-default at 1.24:1, against the 3:1 that WCAG 2.2 SC 1.4.11 requires.

1.4.11 is met if either the fill or the boundary reaches 3:1. Neither did, on any of the three surfaces an input actually sits on. The fix is a new --color-border-input, now 3.11:1 here – not a brighter fill, which would have to clear 3:1 against all three surfaces and would end up reading as a button. --color-border-default and --color-border-subtle are unchanged; 1.4.11 does not govern decorative dividers. An unchecked checkbox is identified by its edge alone too, so it takes --color-border-input for the same reason (#96).

Separately, and under a different rule: the placeholder was 2.69:1. Placeholders are text, so the bar is 1.4.3's 4.5:1, not 3:1 – it is now 4.53:1.
What this card replaces. Five copies of the same dropdown, three text inputs of three different heights, and two entirely different checkboxes shipping in the same window. Two of the five dropdowns have no disabled style, so they still light up on hover when they cannot be used.

The error contract

The contract exists in one place and is missing in the rest. aria-invalid appears in 2 places in the renderer – the comment form fields in CommentParts.tsx, which also name their message with aria-describedby. That is the contract below, and it is the model to copy. The rename and new-file field in FileSystemDialog.tsx does none of it: its <label> is linked to nothing, it never sets aria-invalid, and its message is a sibling <div> the field does not point at (#94).
RuleWhy
The field carries aria-invalid="true"It is how a screen reader knows this field is the problem.
The field points at the message with aria-describedbyOtherwise the message is read out of order, or not at all. A hint and an error both go in the list: aria-describedby="name-err name-hint", error first.
The border changes, and there is an iconColour alone is invisible to some readers. Two signals, always.
The message says what to do“Invalid name” is a verdict. “Cannot contain a space – try my-notes” is help.
The message sits directly under the fieldNot at the top of the form. Not in a toast.
Validate on submit and on blur – never on every keystrokeAn error that appears while the first character is typed is noise, and it re-announces on every key.
On submit, focus moves to the first invalid fieldThe reader lands on the problem, and the field's aria-describedby reads the message out. No separate announcement is needed for one field.
The submit button stays enabledA disabled submit gives no reason. Let it be pressed, then move focus to what failed.

Messages that are not about one field

MessageWhere it is announced
A field error, on submitNowhere extra – focus moves to the field and its description is read. The message is not a live region, or it is read twice.
A field error, on blurNowhere extra – the field is already named; the reader hears it on returning. Do not steal focus on blur.
Several fields fail at onceFocus still goes to the first. A count above the form (“2 fields need attention”) is optional and, if drawn, sits in a role="status" region.
Saved, or could not saveOne polite role="status" region per surface, present in the DOM before the text is put in – a region inserted together with its text is not announced. A failure that blocks work uses role="alert" (see Feedback).

Naming a field

Every control has exactly one name, from exactly one source. Either a visible <label for> tied to the control's id, or an aria-label when there is genuinely no visible text. Never both – they compete, and the reader hears the wrong one. A title is never the name (see Tooltip).

The name is short. A sentence that explains the control is a description: its own element, linked with aria-describedby – never inside the <label>, where it becomes part of the name. The checkboxes above are built that way.

Some fields in Erfana have neither name source – the rename field, on the path for every rename, new file and new folder, is one (#94). And a <label> with no control is not a label – it is a heading. Use a <span>.
Proposed addition, not yet part of this decided card: a multi-line field. HTML preview comments need a textarea – four lines to start, grows by dragging, a character counter beside the hint (glyph plus colour from 3,600, an error past 4,000), and Cmd/Ctrl+Enter to save the focused field. It uses this card's border, ring and error contract unchanged. It is drawn in the proposed Comment window screen and joins this card when that one is promoted.

Sizes

3 renderer stylesheets size a field with these tokens today; every other field sets its height by hand or lets padding decide it, so the same control is a different size depending on which dialog you opened.

TokenValueSampleUse
--input-height-sm28px
Dense chrome – the find bar, a toolbar field.
--input-height-md36px
The default. Dialogs and settings.
--input-height-lg44px
A single prominent field on its own.

A button on the same row as a field takes the field's height – see Buttons – Beside a field.

The keyboard contract

KeyResultFocus ends on
TabNext control; a disabled one is skippedThat control, with the ring
Space on a checkboxToggles itThe checkbox
Enter in a single-line fieldSubmits the form; if a field fails, nothing is savedThe first invalid field, or wherever the action sends it
Esc in a dialog fieldCancels the dialog; the typed value is not savedThe control that opened the dialog

Exceptions

None recorded. A shipping component that departs from this card carries a deviates: marker at the site and gets a row here, naming the file.
