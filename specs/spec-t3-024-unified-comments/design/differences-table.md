# Differences between the HTML and Markdown comment experience

Approved by the owner on 2026-10-29 (pre-approval given in the session that built spec 024; recorded per the owner's instruction). See [approvals.md](approvals.md).

Requirement: 024-FR-006 (and 024-FR-007 for words). Acceptance: 024-AC-007.

*Owner decision (2026-10-31):* every comment message was rewritten for readers who are not developers, in one approved table. The HTML word "element" became "section", "thread" became "conversation", and the window no longer shows a tag or selector. The strings below are the new ones; a row dated earlier that still shows old wording is history.

*Owner decision (2026-11-01):* after the panel review of both previews, the owner decided these, and this table now says them:

- Both previews use the plain kind word: "New comment on section", "New comment on paragraph", "Comment on section", "Comment on paragraph". The "this" forms are gone (A-01, A-02).
- Tab moves at the same level in both previews, among siblings; Alt+Up and Alt+Down change level (A-15).
- HTML drawer rows, outline labels and the mode tab use plain words; the code (selector) shows on hover only (D-03, D-05).
- There is no Undo for delete. The editor stays as it is: OD-03 stands, with no comment count and no way back (D-25, D-36). There is no visible first-use hint and no visible save note.
- "Resolve all changed comments" is added, with review first ([state-table.md](state-table.md) § 2, 024-FR-028).
- The filter is called "Problems", not "Can't edit" (A-10).

*Review note (2026-11-01):* the rows the review showed as stale are rewritten here and are no longer history (D-03, D-04, D-05, A-01, A-02, A-08, A-10). D-09 and D-10 are not settled: they are under test in plan step 8. § 5 lists the differences the review found that this table did not have. The reviewers read the code and did not run the app, so each § 5 row stands until its plan step tests it; a row that test disproves is closed. The plan may still change other rows: D-12 and D-32 (step 11), D-24 (step 2), D-27 (step 11). Plan: `.local/panel/comments-alignment-plan.md`, which is not in the repository; finding numbers (I-, K-, P-F) come from the panel's reviews beside it.

**Sources**, at commit `de29e70d`, in the order the spec gives (a later one wins; the spec wins over all): [html-preview-comments.md](../../../docs/designs/comments/html-preview-comments.md), [markdown-preview-comments.md](../../../docs/designs/comments/markdown-preview-comments.md), [selection-comments.md](../../../docs/designs/comments/selection-comments.md), [comments-v2.md](../../../docs/designs/comments/comments-v2.md).

**Rule.** The two previews look, read, respond to keys and follow steps the same way. A difference stays only where the file type, or the way the preview is hosted, makes the same behaviour impossible – that is a *forced* difference, listed in table 1 with its reason. Every difference the designs made by choice was aligned (owner decision, 2026-10-29) and is listed in table 2 with the one behaviour both previews now share. No row is *chosen*.

Placeholders: `{kind}` is the Markdown kind noun from comments-v2 C-03 (paragraph, list item, H2 heading, code block, block quote, …); in the HTML Preview the same slot holds the word "section" (024-FR-007). `{label}` is the visible target label: the word and line in the HTML Preview (`Section · line 42`), the kind noun and line in the Markdown Preview (`List item · line 14`).
