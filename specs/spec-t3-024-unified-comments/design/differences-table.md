# Differences between the HTML and Markdown comment experience

Approved by the owner on 2026-10-29 (pre-approval given in the session that built spec 024; recorded per the owner's instruction). See [approvals.md](approvals.md).

Requirement: 024-FR-006 (and 024-FR-007 for words). Acceptance: 024-AC-007.

**Sources**, at commit `de29e70d`, in the order the spec gives (a later one wins; the spec wins over all): [html-preview-comments.md](../../../docs/designs/comments/html-preview-comments.md), [markdown-preview-comments.md](../../../docs/designs/comments/markdown-preview-comments.md), [selection-comments.md](../../../docs/designs/comments/selection-comments.md), [comments-v2.md](../../../docs/designs/comments/comments-v2.md).

**Rule.** The two previews look, read, respond to keys and follow steps the same way. A difference stays only where the file type, or the way the preview is hosted, makes the same behaviour impossible – that is a *forced* difference, listed in table 1 with its reason. Every difference the designs made by choice was aligned (owner decision, 2026-10-29) and is listed in table 2 with the one behaviour both previews now share. No row is *chosen*.

Placeholders: `{kind}` is the Markdown kind noun from comments-v2 C-03 (paragraph, list item, H2 heading, code block, block quote, …); in the HTML Preview the same slot holds the word "element" (024-FR-007). `{label}` is the visible target label: the element selector in the HTML Preview (`button.cta`), the kind noun and line in the Markdown Preview (`List item · line 14`).

## 1. Forced differences

| # | Area | HTML Preview | Markdown Preview | Forced or chosen | Reason |
|---|---|---|---|---|---|
| D-01 | Comment window modality | Modal: focus is trapped, the page freezes to a still image while the window is open, a click outside closes the window | Non-modal: the preview stays live and scrolls, the window follows its block, an outside click does not close it, F6 moves focus between window and preview, the window collapses to an edge tab when its block scrolls away (C-18) | Forced | The HTML page is a native view drawn above Erfana's own window, so Erfana cannot draw over a live page; the page must freeze, and the area outside the window is a picture that cannot be used, so a click there means "leave". The Markdown preview is Erfana's own DOM, where a click outside is real work (scroll, select, open another comment) |
| D-02 | Window placement | Right of the element → left → below → above; a sheet over the page area under 400 px | In the margin right of the text column when 376 px are free (from about 1,612 px of preview width, R-15), else right → left → below → above; edge tab when the block is off screen | Forced | Follows D-01: only a non-modal window can sit beside a block that keeps scrolling |
| D-03 | Visible target label | The element selector, mono (`button.cta`), in the context line, drawer rows, mode tab and outline label | The kind noun and line (`List item · line 14`); no tag names | Forced | 024-FR-007: an HTML user picks an element, and the selector is the only way to tell nested elements apart; Markdown source has no tags, and a tag name is not a word a Markdown writer uses |
| D-04 | Target word in sentences | "element" (window titles, banners, announcements, menu items, empty drawer, moved-draft text) | The kind noun ("paragraph", "list item"); never "element", "page" or "block" | Forced | 024-FR-007. Every sentence uses one template with a `{kind}` slot; only the word in the slot differs |
| D-05 | Floating label at the outline | Kept (selector; pixel size only while Alt is held); moves inside the outline's top-left corner when the outline touches content (C-21) | None; the comment-mode tab names the target | Forced | On an unknown page, nested wrappers often share one box, so the outline alone cannot say which element is picked; the label at the outline is the only cue where the user is looking. In the Markdown column the label covered the line above (C-21), and every block has its own box |
| D-06 | Ring on the picked target | Two-tone ring (accent ring with an ink line), colours passed in by main | The one focus ring of the Focus card | Forced | The page's ground colour is unknown, so a one-colour ring can vanish; Erfana's preview ground is known (D-4 in comments-v2 § 8.1, answered by the owner) |
| D-07 | Comment icons for assistive tech | Visual only: the icon layer is `aria-hidden`, icons have no role, name or tab stop; the drawer and the stepper are the route | Real buttons outside the Tab order, pressable with Enter and Space, named ("2 comments on list item, line 18. Open."); the commented block carries `aria-details`; the stack icon and the ghost icon are named too | Forced | HTML icons live in a closed shadow root inside an untrusted page in another process, where assistive-tech activation is not reliable (C-11). Erfana owns the Markdown DOM |
| D-08 | How the underline is drawn | Boxes in the overlay's shadow root, one per line rectangle | CSS custom highlights (`::highlight(erf-comment)`) | Forced | The highlight registry and its `::highlight` rule would be visible to page scripts (selection-comments § 5.5). The look is the same (Text highlights card) |
| D-09 | Click on an underline | Opens the thread only in comment mode | Opens the thread in any mode | Forced | Outside comment mode the HTML page owns its clicks |
| D-10 | Comment button after a mouse selection | Shown only in comment mode | Shown in and out of comment mode | Forced | Same as D-09: outside comment mode the page owns the mouse (OD-01, C-16) |
| D-11 | Right-click outside comment mode | Erfana's menu appears only when the page did not cancel its own right-click; the menu holds comment items only | Erfana's preview menu: comment items, then the prompt items and Copy selection it ships today | Forced | Page scripts own the HTML page's right-click (OD-01). The comment items are the same in both (menu matrix); the prompt items and Copy selection are the Markdown preview's existing menu, outside this spec |
| D-12 | Not-found comment in the preview | No icon | A dashed ghost icon at the comment's place between two blocks ("Comment not found, line 12. Open.") (C-05, R-16) | Forced | An HTML comment node has no layout box, and CSS or scripts can place the elements around it anywhere; a Markdown comment sits between two blocks of Erfana's own column, whose positions are known |
| D-13 | Hidden target – where it may be | "…it may be on another slide or tab." | "…it may be inside a collapsed section." | Forced | Different causes: pages hide elements with scripts and CSS; the Markdown preview hides blocks in collapsed sections. One sentence template, one slot |
| D-14 | Elements a script builds | Commentable: saved before the nearest element in the file, with a snapshot; "Added by a script – saved before <{ancestor}>."; label suffix " · script"; "Narrow to words" hidden | Does not exist | Forced | Only HTML pages run scripts |
| D-15 | Frames | Same-project frames are commentable and saved in the frame's own file ("Saved in {frame file}."); inline and refused frames are not | Does not exist | Forced | Markdown has no frames |
| D-16 | Selected words not in the file | Main can refuse `sel` as not in the file: "This text isn't in {file} as written – a script may have changed it." with "Comment on the whole element instead"; words in a script-built element are accepted unchecked | The same check runs on the same code path, but should never fail; a failure is logged as a bug and shows the same window text with `{kind}` | Forced | Only page scripts can change text after the file is read (024-FR-004 rule 1 applies to both) |
| D-17 | A selection across several targets | Goes to the smallest common parent element; cut to the element where it started (with the cut notice) only when that parent would be `body` or `main` | Always cut to the block where it started, with the cut notice | Forced | 024-FR-004. A Markdown block's parent is usually the document itself, which has no slot; HTML parents are elements that can hold a comment |
| D-18 | Where the comment goes in the file | Directly before the element's start tag: on lines of its own when the tag starts its line, else mid-line | Always on lines of its own, at the slot the Markdown placement rules give: before the whole list for item 1, after the previous item for item 2 onward, before the whole table or block quote for what is inside them ([markdown-format.md](markdown-format.md)) | Forced | Markdown has no start tags, and a comment line in the wrong place changes how the file renders (markdown-preview-comments § 5) |
| D-19 | Context line when the comment is not right before its target | "Added by a script – saved before <{ancestor}>." | "Saved before the {list \| table \| block quote} on line {n}." | Forced | Follows D-14 and D-18 |
| D-20 | Pre-save check and its refusal | Same element tag sequence before and after; the `<meta charset>` prescan refusal | The rendered tree is the same before and after; refusal "Erfana can't add a comment to this {kind} without changing how {file} looks in the preview." with a re-target button (C-19.3) | Forced | Each file type has its own way for a comment to change the result: HTML through element structure and the charset prescan, Markdown through block structure |
| D-21 | `--!>` | Closes a comment (HTML parsing rules) | Does not close a comment; the file is read-only as unterminated | Forced | 024-FR-003: CommonMark ends an HTML comment block only at `-->` |
| D-22 | Finding the target again; what "Changed" compares | Position can attach on the tag alone when the anchor has no `id`, path or quote; "Changed" compares text, `id` and classes | A text (quote) match is always needed – position alone gives Not found; "Changed" compares text only | Forced | Every Markdown paragraph is a `p` with no `id` (only headings have one), so position alone would hand a comment to its neighbour (024-FR-003) |
| D-23 | Target moved between pick and save | The window offers Pick again; your text comes with you (C-14.1) | Saved to the one block that matches the stored quote ("Comment saved to {file}, line {n} (the {kind} moved).") else refused as moved, with Pick again | Forced | An HTML pick is a token in one served copy of the page, which is gone once the file changes and the page reloads; a Markdown pick is a line and a quote in text Erfana parses itself (024-FR-013) |
| D-24 | Unsaved editor edits to the same file | Only saving is blocked: a banner in the window, "Save {file}" and "Go to tab" | The whole comment surface pauses: a band across the preview with "Save {file}" (or "Go to editor" when the file also changed on disk); Reply, Resolve, New comment and comment mode are disabled; the count stays clickable (C-09, 024-FR-015) | Forced | The Markdown preview draws the editor's unsaved text, so marks would land on the wrong blocks; the HTML Preview draws the file on disk |
| D-25 | View modes | One view | Comments only in the preview-only view; editor and split views show none; a draft survives the switch ("Draft restored") (OD-03, 024-FR-005) | Forced | The editor and split views show the raw blocks as text |
| D-26 | After a save | The page reloads; scroll and `#hash` are restored | The preview re-renders in place | Forced | The HTML page is a separate document that must load the changed file |
| D-27 | Read-only and unavailable reasons | Non-UTF-8 (including a legacy `<meta charset>`), 25 MB or 640,000 elements, overlay removed by the page, page replaced its document, couldn't prepare the page, inline or refused frame, an element that cannot hold a comment (`html`, `head`, template content) | Frontmatter is not commentable; size, line and nesting limits from the corpus (024-NFR-008) | Forced | Each reason exists only in its file type. The shared reasons (git conflict, link, too many comments, outside the project, generated region) read the same in both |
| D-28 | Toolbar row the tools sit in | The preview's permission band: band tool size and its narrow tiers | The Markdown toolbar: 32 × 28 tools, one Tab stop per control, as it ships (markdown-preview-comments § 9.1) | Forced | Each preview already has its own row; the comment tools take the row's size and key model. Tools, order, names and states are the same |
| D-29 | Font of the quoted words in the window | System sans | The preview's serif | Forced | Erfana does not know the page's font; it does know its own preview font (selection-comments § 7.1) |
| D-30 | Text in the "Narrow to words" field | The element's visible text from main's parse5 parse | The block's rendered text from main's Markdown parse | Forced | Different parsers for different file types. The field, keys and result line are the same |
| D-31 | Where keyboard focus lives in comment mode | Keyboard entry moves focus into the page; the preload handles the picker keys | The preview scroller is a tab stop; the picked block takes real focus | Forced | The HTML page is another process; keys typed there never reach Erfana's window. The keys themselves (Tab, Shift+Tab, Alt+Up, Alt+Down, Enter, Shift+F10, Esc) are the same |
| D-32 | Drawer help note about changes | "Changes to attributes or styles only are not detected." | Not shown | Forced | Markdown blocks have no attributes or styles of their own to change |
| D-33 | Agent-facing text | HTML agent note; the `target:` line names tag, `id` and class | Markdown agent note; an extra "target in Markdown" hint line in the note area | Forced | Agent text is exempt from 024-FR-007; a Markdown `target:` line such as `<li>` gives an agent too little to find the block (C-01, C-02) |

## 3. Checked and the same

Checked in the designs and found the same in both, so no row: the shortcut (⌥⌘M / Ctrl+Alt+M), the Esc order (menu → window → comment mode → Find), the gesture table (click, double-click, triple-click, drag of 4 px or more, Shift+click, right-click), the stepper and its keys (⌥F9 / Alt+F9, ⇧⌥F9 / Alt+Shift+F9), "Resolve and next" and "Reply and resolve", the window foot order, drafts and "Draft restored", the 200-character words limit and its notice, Rebuild from data (OD-05), the removed-outside note (OD-06), no folder refusals (OD-07), file-only comments (OD-08), the pressed look of the mode toggle and the open drawer's count, the count text ("7 comments ▲1"), the "Show comment icons and underlines" checkbox, the icon position rule (top-right corner, 4 px outward), the comment mark look, Changed and Words changed with Was/Now, and every save-error sentence apart from the `{kind}` word.

## 4. Adding a row

An extra difference found at owner acceptance (024-AC-007) is either fixed before merge or added to table 1 as *forced* with its reason. A row that cannot give a file-type reason is not forced; it is aligned instead.
