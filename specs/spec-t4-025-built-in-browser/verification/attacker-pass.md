# Attacker pass: address bar and origin spoofing

Run 2026-11-03 on `wt-spoof` (from `9a802d9b`) for issue #448, DoD § 4: "each attack that works becomes a regression test". Scope: every surface that names an origin – the address bar at rest and while edited, the editor-tab label, history and suggestion rows, the popup's origin strip and OS title, the load-error page – against the rules in `docs/designs/browser/README.md` § Security UI rules 1–3 and design § States › Tiers (fold steps 2 and 8).

The findings came from a read-only pass; each was re-checked against the code before it was fixed. "Before" is the behaviour at `9a802d9b`; "after" is this change. The e2e tests are in `e2e/browser-origin-spoofing.e2e.ts` (`origin spoofing – attacker pass (issue #448)`), run with `--repeat-each=3` on macOS.

## Side note fixed

Downloads: `iso`, `img`, `vhd`, `vhdx` (disk images Windows mounts on a double-click), `chm`, `cab`, `xll` and `library-ms` now count as executable types and get the save-dialog warning (S-18; the spec does not list the types). Unit: `downloadFileName.test.ts` › `isExecutableDownload – attacker pass (issue #448)`.

## Open
