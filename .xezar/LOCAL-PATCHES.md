# Local kit patches

This file lists local changes to copied kit files that an upgrade must preserve or upstream, so a kit refresh does not silently remove project-specific operating guarantees.

- Added `.xezar/docs/briefs.md` and linked it from the kit documentation and leader-guide detail to standardize row-specific dispatch briefs for issue #175.
- Configured the repository gate's two application lanes in `.xezar/pipeline/config.json`, bounded its config read in `gate-parallel.mjs`, recorded and checked the resolved schedule at execution, kept coverage ahead of unit tests and build with fail-closed command guards, and switched lint to read-only `lint:check` for issue #169.
- Dropped `npm run test:ci` from the canonical gate list for issue #170: removed it from `GATE_NAMES`/`GATE_COMMANDS` in `.xezar/checks/repo-gates.sh` (new command-list id) and from `validation.commands` in `.xezar/pipeline/config.json`, moved the committed lanes to `3,4,5,6,9;7,8`, and replaced the unit-tests-share-a-lane guard in `.xezar/checks/lib/gate-parallel.mjs` with a refusal of any list that names `npm run test:ci` again, keeping the coverage-before-build and renamed-command guards. `test:cov` runs every main, preload and renderer unit test once and enforces the floors, so the removal is safe only while `test:cov` stays one `--project` pass per project (#133). Tests: `gate-parallel.test.mjs` updated; `lib/gate-results.test.mjs` added to show attempts sealed under the old and the new list id both seal and verify. The kit's generic copies still carry the old guard and list.
- #170 review round 1 (PR #191): `.xezar/checks/lib/gate-parallel.mjs` now binds its guards to gate identities – the whitespace-normalised executable command as well as the label. `test:ci` is refused as a word in either the label or the command (so `npm run-script test:ci`, a respaced name or a relabelled entry are refused too). `npm run test:cov` and `npx electron-vite build` are both mandatory whenever application gates run: a missing, duplicated or label/command-mismatched identity is refused, so renaming both no longer switches the coverage-before-build guard off (closes #186 S-5). This diverges from the kit, whose scheduler lets a project run application gates without these two. `gate-parallel.test.mjs` runs the guarded gates through stand-in `npm`/`npx` on `PATH` and adds alias, whitespace, label/command-mismatch and both-renamed refusal tests. `.xezar/checks/repository-checks.sh` now also runs `lib/gate-results.test.mjs`, beside `gate-parallel.test.mjs`.
- #170 review round 2 (PR #191): `.xezar/checks/lib/gate-parallel.mjs` no longer matches words. It carries `APPLICATION_GATES`, an explicit allowlist of canonical application-gate identities (label plus exact command string: lint:check, lint:css, design --check, typecheck, test:cov, electron-vite build, check:headers – what `repo-gates.sh` ships), and refuses any application entry that is not exactly one of them after trimming outer whitespace, or that is named twice. An extra suite (`npm test`, `npm run test`, a quoted script name, `test:ci` under any label), an unknown command and a harmless new label are all refused with a message naming the allowlist, so adding an application gate is an explicit edit to this file. Coverage and build stay mandatory, with coverage before build in one lane. This replaces the round-1 word match and diverges further from the kit, whose scheduler accepts any application command. `gate-parallel.test.mjs` runs every shipped gate through stand-in `npm`/`npx` on `PATH`, checks that `repo-gates.sh --list --json` application gates equal the allowlist and are accepted, and adds quoted-argument, `npm test`, `npm run test`, unknown-command, harmless-mention, duplicate and both-removed refusal cases.
- Bounded the injected timeline in `.xezar/checks/leader-context.sh` to its newest 40 entries with a pointer line to the full file, and made it name any `archive-*.md` it does not load; added `.xezar/checks/decisions-archive.mjs` (moves resolved `decisions.md` entries verbatim into `archive-decisions.md`, never deletes) and `.xezar/checks/leader-context.test.mjs`, run from `.xezar/checks/repository-checks.sh`; documented both in `.xezar/docs/leader-context-loading.md` and `.xezar/docs/campaign-notes.md`, for issue #174. `decisions.md` is still injected whole. Round 1 of #201 review: the archive script takes an exclusive lock file, stages and reads back both files before replacing either, refuses if `decisions.md` changed mid-run, and confines the campaign path to the repository's real `.xezar/campaigns`. Round 3 (owner-approved) replaced the rewrite design: the script only appends verbatim copies to `archive-decisions.md` (never rewrites, renames or deletes a file; `--to` removed), `leader-context.sh` leaves out any `decisions.md` entry byte-identical to an archived one via the script's `--visible` filter (whole file if the filter cannot run), and it prints a loud warning when `decisions.md` is missing or unreadable. The lock only prevents duplicate appends and is removed even if its close fails. Round 4 (owner-approved): matching is on exact original bytes and bound to one occurrence – each archive record carries the SHA-256 of the entry's bytes plus its ordinal among identical entries between begin/end marker lines; the loader hides only occurrences named by a complete, hash-checked record, and any malformed record hides nothing (whole file plus a one-line note). Round 5 (leader-approved, parked): the ordinal is replaced by the entry's byte offsets plus the SHA-256 of its bytes and of the decisions.md prefix to its end, so an edit, insertion or reorder at or before an entry makes its record stale (ignored, counted in a loader note) instead of moving it onto another entry; the script re-reads decisions.md and records only entries present in it.
