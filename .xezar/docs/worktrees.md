# Worktree and setup discipline

Every writing task owns .local/xezar/worktrees/<runId>, on xez/<first8>. Xezar owns creation/retention. Do not adopt a branch, use a peer checkout, or fall back to root after reclaim. Bootstrap copies only allowlisted maintained kit files after validating primary repository/task/branch; it refuses symlinks and conflicting existing files. It never copies the current root application's dirty changes. Run preflight before every write and on continuation; errors show actual CWD and predicate.

Setup checks Node >=20/npm and npm ci freshness, then writes task context. Freshness covers package-lock.json, npm-shrinkwrap.json, package.json, .npmrc, patches, workspace manifests and Node/npm versions, and requires every workspace package to resolve to the task's own copy: a task worktree sits inside the primary checkout, so a missing `node_modules/<workspace>` link silently loads the primary's source instead (#286). Setup and the gates refuse such a tree; a command run by hand before setup is not guarded, so run setup first. With `dependencies.units` (read from the base branch) setup and the first gate both run `.xezar/checks/deps-restore.sh` instead: each unit is installed in turn (`npm ci`, Yarn 1 with a frozen lockfile, `dotnet restore <entry>`), freshness is a stamp per unit under .local/xezar/cache/deps, and a numeric root .nvmrc pins the Node major from an already-installed nvm version. Never copy node_modules or credentials. Read-only initialization makes only evidence context; code execution needs an independently prepared isolated checkout. No fabricated run ID.

Use worktree-git.sh commit/push with current CWD and task identity; it binds named ref and refuses merge-in-progress. Reuse original task/PR for corrections. Missing ownership needs deliberate recorded migration, not an incidental duplicate. Results that must survive retention live under primary .local/xezar/tasks. No archive-before-reclaim mechanism is presumed necessary; preserve non-rebuildable evidence explicitly.

Source snapshots are recorded as .local/xezar/cache/kit/snapshot.json in the ignored task runtime tree. Bootstrap never refreshes an existing task snapshot. A differing tracked asset is kept only when it equals the fork base's blob (`git merge-base HEAD origin/<base>`), which is the primary checkout lagging a merged kit PR; any other differing asset, or no reachable fork base, is refused instead of overwritten: use that revision's own kit or a deliberately reconciled later task, not a hidden update. No generic product seeding behavior has been added.
