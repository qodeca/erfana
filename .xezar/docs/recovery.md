# Recovery, integration and root sync

First read current task checkpoint/late steering and actual identity. resume-complete.sh --dry-run diagnoses remaining stages without effects (exit 2 means work remains); normal resume reuses only currently eligible evidence, otherwise runs needed gates/seal. Printing checkpoint pointers is not consuming them: the agent must read them. Do not replay an entire workflow or trust old green status. BLOCKED must stop normal readiness.

Merge recovery: record intended operation with merge-recovery.sh before a separately authorized merge. Only a matching single merge may recover; ordinary worktree-git refuses resolved and unresolved merge markers. Never invent retrospective intent or automatic abort/reset. Mechanical recovery does not grant business authority or waive normal readiness. Read --help for exact arguments.

Integration Mode A: named PR, main, exact head/base, existing authority record and current real policy/checks. integration-preflight.sh is read-only. Apply SDLC label/QA rules as well as hosting protections. Unknown API policy is not zero approvals; pending is not passed; already merged is reconciliation. Xezar uses squash merges per SDLC: verify the single parent/base and resulting content/commit, not a two-parent merge assumption. Verify CI at the resulting commit and remaining business scope.

Root-sync Mode B is separate, Worktree OFF, actual engine root lock enabled, expected root/branch/head and fixed target, clean tree and fast-forward only. root-sync-preflight.sh cannot prove the manager lease: verify actual runtime ownership before mutation. A record or git -C from another worktree is not a lease. Finish promptly, release resource, record already-current no-op. Local fixtures do not prove live engine scheduling.

## Continue and delivered context

Continue (the cockpit's Continue, or the leader's MCP `execution_control continue`) opens a synthetic interactive agent step. After DONE, unfinished workflows resume at the failed check (or after the interrupted agent step) and execute the remaining definition; fully completed runs stay agent-only follow-ups. Continue does not guarantee reinjection of the selected step skill. Before editing, verify actual CWD, task/branch identity and strict preflight. Requested isolation must remain isolation; rematerialization refusal is a blocker, not authority to edit primary. Supply the original role, remaining stages, accepted decisions and predecessor attempt IDs explicitly when changing backend/session. Inspect the delivered body and referenced content, not just the workflow name.

Task-local kit snapshots, persisted workflow definitions and actually delivered skills are distinct. Skill discovery and companion reads may use current primary/installed content on new turns or Continue. Record relevant body/reference versions (or unknown) before claiming unchanged context. An absent delivered-body/reference version remains unknown even when the task-local snapshot is present. For old snapshots or changed policy, preserve historical bytes and evidence, compare the current command/check requirements, and use an ownership-preserving supported refresh/revalidation path. Never overwrite active snapshots or waive missing current checks. If no safe refresh path exists, report that specific blocker.

After a recorded BLOCKED decision is actually resolved, consume the answer and late steering, diagnose with resume-complete.sh --dry-run, complete owned content/commits, then run normal resume for eligible remaining gates and seal. Handoff, independent review, QA and integration remain separate even when Continue ends done.

Shared review tools must preserve role independence: do not use a convenience review that checks out, adopts or amends a same-account peer PR. Use xezar-code-review for immutable assessment, return repairs to the original author, and xezar-integration for the current project guard plus SDLC's comment-based active QA. Loading a shared skill does not qualify its tools, paths or authority assumptions on another backend.

Recovery qualification limit: old cleanup can erase both worktreePath and branch. Those legacy records cannot be distinguished from intentional legacy in-place runs; do not qualify them for isolated Continue merely because the runtime accepts them. Recover actual identity and use a separately authorized isolated task when it cannot be restored. No empty metadata is proof of requested in-place authority.

Observed OpenCode recovery limit: recreating the installed 0.13.0 server runner created a new vendor session despite a requested prior session ID. A correction-only prompt therefore lacked the original role and tool boundaries. Verify the effective session ID and resend the complete required context when history reuse is unproven; requested resume metadata is not proof of delivered history. Native vendor-history reuse remains unqualified.
